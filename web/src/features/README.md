# 前端页面

一个页面一个目录：`report`（含共用的 `foot.ts`）/ `settings` / `system` / `run` / `rail` / `favorites` / `lookup` / `overview`；通用件在 `web/src/components/`。前端不碰数据源与数据库、不自己算分，页面上每个数字都来自 `/api/v1`。

## 报告卡

卡片是唯一的交付物：折叠状态下所有卡片等高。

| 规则 | 说明 / 反例 |
| --- | --- |
| 折叠状态下**所有卡片等高**：`结论` 固定十行（`--verdict-lines`），放不下的部分由**卡片右下角的「展开」按钮**打开，不是 hover 弹层（弹层无法固定，且会盖住下面那张卡）。「链上质量」与「链下调研」两块**默认折叠**；顶栏那个按钮一次开合全部，做法是**不接管 `details`**（换 key ＋ 给新默认值，使它们连同结论一起重新挂载）。 | 给分项添加说明性文字就会换行（卡片窄）。默认展开就把卡片撑高，「结论在前、数据一键展开」这套重排失效。 |
| **卡片头部是两行身份**：最左是图标方框，右边上下两行 —— 上行 `标的` ＋ `新进/续榜`，下行 CA（截断）＋**复制 icon**（点击变绿换对勾）。**CA 与复制钮都没有框、没有底色**：地址位于名字下面，带边框时像输入框；复制钮也**不能填 `--surface`**（前三名头部有底色，填了会露出一个矩形）；概览表里那个复制钮仍有框（它单独站在单元格里），两种用法各写各的。头部右上角上下两行：上行 `综合分`，下行 `排名`（两位序号，前三名颜色跟到这一行），`重新搜索` / 星标与它们同行。 | 池内排名（`流动性 · 成交 · 持有人`）因此单独一行右对齐 —— 它原先是 CA 那行的右半边，地址挪上去之后同行放得下 CA、放不下排名。评分条把两块画成两段，**不带 ×55% 这类占比文案**。 |
| 貔貅是**判定不是数字**：读 GoPlus 的 `is_honeypot`，输出「是 / 否 / —」三态带**色框**（复用安全区 pill 的配方）。**LP 也只分三态**（已锁 / 未锁 / 未判定），显示「已锁」时不跟括号解释，标签本身就是答案。CSS 必须写成 `.kv .kv-v.hb-*` 才能覆盖缺值行的灰字。 | 两层的写法会**静默失效**。陷阱占比由「陷阱」chip 承担（`honeypot_pct`）—— 两者不是同一个数，不应把同一个值放在两个名字下。 |
| 「链上质量」表**不输出**开盘与总供应、洗量、机器人 / 新钱包 / 私人金库 / 优质持有人 / 信号数，**筹码分布与池子清单也已移除**（payload 里仍带着，供归档与 API）。 | GMGN 在 Arc 上对这些一律回 0，一整行 0.0% 属噪声，输出后反而会淹没有价值的行。 |
| 「本轮摘要条」＝ 日期步进 ＋ `扫描 -> 淘汰 -> 候选 -> 入选` ＋ `已判定 / 未判定` ＋ 本期变化 chips（新进 / 退出），**一行到底、字号与颜色统一**；退出项显示**币的名称**而非 CA。**日期控件属于报告页**，与首张卡片对齐。 | 三块分割线画到边框上，整行会被切成三个盒子。放到全局顶栏，设定页上也会出现一个改了没有作用的控件。 |
| **展示层的链接一律「说明 ＋ 可点击词」**，不输出裸 URL。**头部有币的图标位**：在名字左边，方框**大小就是旁边那两行身份的高度**（头部由文本定高，方框怎么变形都不影响其他元素），描边走 `--accent`、**直角**（见 `styles/README.md` · 视觉）；尺寸由调用方（`Logo`）给。图按 `dexscreener` → `geckoterminal` 取（分别是 `info.imageUrl` 与 pools 响应里 `include=base_token` 那张），两条都是**已经在请求**的响应，所以**不增加请求、不增加数据源、不增加费用**；GMGN 也有图，但它的 CDN 只认自家引用，不进这张表。存的是 **URL** 而不是字节（卡片是拷贝、会被归档）。**没图时留位**（空格子填 `--logo-empty`，深色纯黑 / 浅色纯白），加载失败也退回空格子，不留破图。 | 空格子是白底落在近白卡片上，用 `--border` 几乎看不见有没有格子，所以描边走 `--accent`。把图当作次要元素（有则画、没有则不画）会让同一行的卡高度不一致，收藏页上搜索卡与轮次卡会错位。 |

## 侧栏与顶栏

侧栏回答「我在哪」，顶栏只放当前页面的动作。

| 规则 | 说明 / 反例 |
| --- | --- |
| 左栏只渲染 `enabled` 的链：未接的整行不出现（不是变灰），链名旁不标注计数（入选数在「本轮摘要条」里）。链名取 yaml 的 `label`；**`label` 是雷达的名字，`name` 才是链自己的名字**（见 `report/README.md` · 词条文字）。 | 把未接入的链渲染成灰行，等于每轮都提示用户「此处内容缺失」。 |
| 顶栏右端 ＝ **当前页面的动作**，同一时刻只存在一份：报告页 `本轮总览 › ｜ 导出 ｜ 推送 TG`，设定页 `配置切换器 ｜ 配置管理 ｜ 保存并生效 ｜ 立即运行`。不可用的动作**灰显不可点**、`title` 写明原因；点击后会打开抽屉 / 面板的那个末尾带 chevron —— 那是这一排里「会离开本页」的唯一记号。 | 两页的动作同时列出来，会让用户分不清哪个属于当前页。 |
| 动作行**最左端**是「运行结果」开关：它折叠的是整条顶栏**下面**那层面板，属于这一轮、不属于当前所在的 tab，所以排在动作行第一个。这是**唯一**的折叠处 —— 面板自己没有关闭按钮，所以「已停止的一轮把页面交回去」搭在它的**收起**那一半上（展开时不改变位置）。 | 放在 tab 组旁边，会被读成它切换的是右边那片内容 —— 它折叠的是整页下方的面板。 |
| 刷新要落在原来那一页：链 / 配置 / tab / Place 四个选择写 `ch.*`（读法就是 `useState` 的初值）；**报告轮次下标不存** —— 它由打开页面时的那一次列表请求给出，存下来会与那份回答冲突。链列表**里面**、紧跟最后一条链的是 `搜索` 和 `收藏` 两行（`搜索` 在上），**不画分隔线、不留额外内边距**，四行**同墨色**；**同一时刻只有一行是亮的**（链行亮起即位于该雷达且是当前链；在收藏页上链行全部熄灭）。 | 同时存下轮次下标，下一轮跑完后刷新会打开一个旧批次。把这两行调淡，会被误读为不可点击；两行同时亮，会被误读为收藏页属于那条链。 |
| 「系统设置」是**一行 rail 行、也是一个 Place**：它不属于任何链，所以排在链与两条收藏页那一列之下、主题开关之上（`.nav-foot` ＋ `.nav` 是列 flex），侧栏中的全局项都落在这一带。**它是页面而不是 tab**：打开就是整页表单，没有 `搜索 / 设定` 那对 tab；**同一时刻仍只有一行是亮的**。 | 放在某条链的 tab 组里，会被误读为这份接线属于那条链；放在最上面，等于告诉用户它比链还常用。 |

## 收藏页

收藏是**那份组装好的卡片的一份拷贝**，不是指针：报告行随轮次消失，报告库还可能被整套删除，指针留着就只剩一条断链。主键 `(chain_id, ca)`、**不带 `config_id`**（搜索能收藏任何链的币）。**写入口三个**：报告页的星 `POST /favorites`（服务端从组装好的那批卡里拷一份，所以拷贝与报告页画的一模一样）、收藏页与搜索页的星 `DELETE`、搜索页收藏一张已在库中的卡只翻转 `kept`。

| 规则 | 说明 / 反例 |
| --- | --- |
| 收藏页自己那条上只有标题一个词，不输出张数；右侧依次：`展开卡片 / 收起卡片` → 过滤框（宽度足以容纳整条 CA，placeholder 用 `--muted`）→ `导出`（灰显，见 `CLAUDE.md` · 边界与待决）。`来源` / `排序` / 方向**不在这条上**，站在卡片左边的面板里；筛选与排序是页面状态，**不落库**。 | 会随收藏页内容出现 / 消失 / 换位的控件，用户每次都要重新定位；两个 label 宽度不同的按钮会让旁边那颗来回移动。 |
| 卡片的**第二条页脚**（只有收藏页传、报告页不传就不画）：第一行 `链: 链名 ｜ 配置: 配置名`，第二行 `生成时间: x ｜ 收藏时间: x`。没有配置文件的链把 id 变成名字（三个字母及以下全大写，更长只大写首字母；**id 本身保持小写**）。时间只到分钟、不带时区。**一个字段的值缺了就连标签一起不画**，不留破折号。 | 框外那一行是页面注脚，框内这一行才是这张卡的出处。 |
| 一轮写完就更新收藏页：把这一轮写过、收藏页上已有的那几张卡换成本轮的新卡。四条边界：**只换不增**（无人收藏的币不进收藏页，那相当于由程序代替用户决定是否关注）、**只同链同设定**、**只往新的方向走**、**不动 `origin`**；`saved_at` **不动**（那是用户收藏的时刻）。 | 收藏跟随的是**币**而不是某个时刻：用户点星之后，每一轮都会自动更新为当前答案。`收藏时间` 一旦跟随刷新变化，就会与 `生成时间` 变成同一个数。这一步由 try 包裹：收藏页更新失败不影响这一轮发布。 |

## CA 搜索

前面几节讲的是**一轮**；搜索是**一个地址**。左栏「搜索」就是这一页，贴一条 CA 拿一张卡，搜过的都留在右侧卡片区。它不是「一轮的缩小版」：没有池、没有排名、没有设定。工作全在 `api/app/lookup.py`。

| 规则 | 说明 / 反例 |
| --- | --- |
| **链由地址决定**，不由用户选：先问 DexScreener 的代币端点，把同一地址的池**按链聚合**、取流动性**最深**的那条。yaml 里没有的链同样出卡（链上那一半如实留空，`None` ＝ 未判定，不是 0）。**没有「简卡」**。 | 让用户先选链，就是让他回答一个常常不知道的问题；不聚合就按行取，同名 CA 在两条链上都有时会取到较浅的那条，那是另一个币的数据。 |
| **没有分**：综合分是池内百分位，池里只有一个币就没有百分位。**搜索页不渲染任何与分数有关的元素**（序号、`新进/续榜`、池内排名那一行文字、`综合分`、整条评分条一并省略，**不是画成 `—`**）；留着的只有收藏星标和 `重新搜索`。开关是 `Card` 的 `listed`，搜索页**显式传 `false`**。**收藏页里空位仍保留**，所以收藏页给评分条一个固定 `min-height`，两张卡逐块对齐。 | 借一个旧池的百分位、或者自己编一个数，就是「分数只在后端计算」的反面（见 `CLAUDE.md` · 设计取舍）；「0 分」与「未判定」是两件不同的事（见 `pipeline/README.md` · 取值与合并）。 |
| **落一行，不落一轮**：写 `origin='search'`、`kept=0`、`config_id=None`、`rank=None`；卡片仍由报告页那同一个组装函数出，**两张卡的结构须保持一致**；调研**不写 `lexicon`**（词条按「链 ＋ CA ＋ 设定」存）。**收藏 ＝ 翻转 `kept`，不写第二行**，所以星标与收藏页不会互相矛盾；重新搜一个已收藏的币只换正文，那条写入**有意不带 `kept`** —— 该列仅由点星改写。**取消收藏按来源区分**：搜索来的那张只把 `kept` 归 0（仍留在最近搜索），轮次来的那张才真正删除该行。 | 自动收进收藏页相当于由程序代替用户决定是否关注；以搜索覆盖某一套设定的词条，下一轮报告会输出一段未经复核的文字；一律删行，用户取消一次收藏就会丢失自己那次的查询记录。 |
| **秒开**：右栏每一张卡**都是库中存储的那一份** —— 列表查询就带回整张卡，切链 / 换排序 / 过滤都是本地读。所以 `重新搜索` 是**唯一**要再花钱的动作，它是按钮而不是默认行为。默认按**那次搜索自己的时钟**排（`origin_label` `DESC`）。搜索卡的**页脚只有两格**：`链: …` 与 `生成时间: …`（不输出配置，也不输出收藏时间）。 | 点一张卡执行一次搜索，等于每次回顾历史都重新付费一次。把写库时刻显示为「收藏时间」，页面就会出现一个用户从未执行过的动作。 |
| **慢，所以是个 job**：一次搜索读一个币在该链的全部源 ＋ 一次链下调研，量级几十秒到两分钟。入队只答 **202 ＋ 一个 job**，页面轮询到 `done` / `failed`；五个阶段各记 state 与实测秒数。链下没回来**不算失败**：卡照出，note 写明缺的是哪一半。 | 为求「快」而削减超时，只会让**部分时候**少一半数据，而用户无法判断是哪一次；把请求悬置不答，中途失败时用户只拿到一句 500。 |
| 搜索页**没有链 / 配置的 TopBar**：它的顶栏与收藏页共用一条 —— 标题 ＋「运行结果」＋「展开卡片 / 收起卡片」＋ 搜索框 ＋ 按钮。**只有一页**：没有 `搜索 / 设定` 那对 tab，搜索框也不会因为输入为空而禁用。 | 把链 / 配置搬过来，会被误读为这一页跟随当前链；一个只解释自身的 tab，等于一次无意义的点击。 |
| **运行结果面板就是一块面板**：搜索复用一轮的样式表和同一个 Marker。两处不同：进度条是**已结束阶段的比例**，**没有「中止」**（后端没有能停止已入队搜索的机制）。**该按钮永远可点**：这一页本身未排过队时，它展开的是**最近一次搜索**；一条记录都没有时才写「还没有搜索记录」。**排队时自动展开；跑完自动收起，失败除外**。 | 另造一套阶段面板，两边「失败停在哪」很快就会不一致；给一个停不下来的搜索画一个「中止」，就是给出一个点不动的控件（见 `CLAUDE.md` · 设计取舍）；把面板留在原地展开，每次搜索都要先手动关闭一块遮挡结果的区域。 |
| **搜索卡宽 ＝ 收藏卡宽**：两页共用同一条轨道规则 —— 左栏面板写死 320px（第一条轨道），卡片段跨其余轨道，段内再套一层同样的 `.grid`。 | **仅把容器换成 `.grid` 并不够** —— 旧的两栏切法让卡片那栏只剩一条轨道，卡片宽出三分之一。搜索页曾一度跟随雷达的轨道规则（卡片宽度等于雷达卡），代价是面板位于一条卡宽轨道内、卡片区前空出一段空白，而且两页的面板宽度不一样。 |
| **右栏是一片卡片区，没有「选中的那张」**：搜过的地址都在卡片区里，一张卡一个（最多 50 条，后端 `recent(limit=50)` 封顶）；左栏的 `链` / `排序` 筛选与排序的对象就是这片卡片区。 | 旧版是「左栏一张行列表 ＋ 右栏只画选中的那一张」，于是左栏的筛选筛的是行、右栏永远只有一张卡 —— 点击链看起来没有反应。有选中态还须记住「上次查看的是哪一行」，而一片卡片区不需要记住任何状态。 |
| **搜索的链接来自本次读取，而非快照**（一个未补齐过的 CA 在快照里没有行，读取结果为空）：`gather()` 多收一个「已知链接」参数。**只换起点，不换工序** —— 挖链、读页面、写作与轮次跑的是同一段代码，引擎仍会查询、官方时间线仍会读取。官网行来自**证明过的那一个**（只有 `own` 才算），落到卡片那份 metrics 的首位。**记录归用户管**：搜索管理抽屉可删一条或清空，两个写都带 `origin = 'search' AND kept = 0`，所以**收藏过的那行两边都不动**（它是收藏页上的卡）。 | 让搜索改为读快照 ＝ 回答的是「上一轮认为这个币是谁」；若一并省去一步，同一个币就会出现两条路径两套结论，而 CA 搜索整套正是在防这一点。删除时一并摘掉星标，等于一次用户从未执行的取消收藏。 |
| **收藏页的两个控件位于卡片旁的面板里**（2026-10-11 起搜索页共用这一条）：`来源`（全部 / 各链 / `搜索`）与 `排序`（收藏时间 / 生成时间 / 分数 / 名称），底下一段横线之下是**方向**（从新到旧 / 从旧到新、从高到低 / 从低到高、A–Z / Z–A）。方向永远两行、随选中的排序切换文案，所以面板高度不变；**换排序就把方向回到该键的第一项**。两个列表的**每一行都以自己的图标开头**：`来源` 行穿那条链自己的 mark（与左栏共用 `components/chainMark.tsx`），`全部` / `搜索` 戴 `Layers` / `Search`；图标 14px、描边 2.5。 | 下拉框会把「还有其他排法」藏起来，须逐个打开才能知道；而 320px 的面板**在每个断点占用一列卡片**，这一列是为「八个组合一次看全」付出的代价。**输入框留在顶栏**：它与 `来源` 列表同属过滤，但边打边答，不是一列选项。**面板所在的第一条轨道写死 320px，不用 `.grid` 的 auto-fill**（auto-fill 轨道地板 345 且会长）。**没有分数的卡在「从低到高」里仍会排到最后**，不以 0 分参与比较。 |
| **搜索页的左栏是那两个面板**：`链`（全部 / 各链 / `其他`） ＋ `排序`（生成时间 / 名称） ＋ 方向，面板右边就是它们作用的**卡片区**。默认是 `全部` ＋ `生成时间 / 从新到旧` —— 正是后端交上来的顺序。**没有 `分数` 这个键**。`其他` 是唯一不是链 id 的一行，代表「本 App 没有雷达的链」（链由地址决定），**只在卡片区确实存在这样一张时才出现**。**一次搜索落地后 `链` 自动回到 `全部`**。 | 链行按 `chains` 里 enabled 的顺序、永远都在，所以「这条链还没搜过」是一个答案，而不是一个消失的按钮；`其他` 则只在有内容时出现；按下它只能得到空结果，属于只能答空的控件。`链` / `排序` 是页面状态、**不落库也不记进 `prefs`**。 |

## 新机会

左栏「新机会」。前面几节讲的是**一轮**或**一个地址**；这一页讲的是**外面发生了什么**：X 上出现的活动与新项目（2026-10-18 起 X 单源；平台页 / 交易所公告 / 目录 / GitHub 的读取器已移除，名单留在种子 `pending:` 段）。它不读候选池、不读快照、不参与打分，也不属于任何链 —— 工作全在 `api/app/opportunity/`。

| 规则 | 说明 / 反例 |
| --- | --- |
| **面板的筛选组只有两组：生态（第一）+ 状态**（2026-10-19, user）：生态是读者真正会浏览的轴（"BTC 生态有什么、Eth 生态有什么"），状态是页面必须能回答的那个问题（为什么它不在列表上）。其后是前端加的「已处理」「队列」入口与「排序」，它们不是筛选值。类别 / 核实 / 类目 / 门槛 / 热度 / 来源都**不是筛选组** —— 它们是卡片上的读数。 | 46 行的面板里，一半是死选项（选"活动"时项目类目必然为空）；把卡片上已经印着的读数再做一遍筛选，读者只是多滚一屏。 |
| **两类合并在页面上**（2026-10-19, user）：`kind`（活动 / 项目）只是**内部读数** —— 它决定抽取问什么、用哪套门槛；页面不再按它分组，卡片**按内容渲染**（有步骤就列步骤，没有就一句"是什么"）。 | 实测这个区分已经退化成"有没有步骤"（54 条里 41 条有步骤，`kind=project` 的 13 条恰好就是没步骤的 13 条），而它换来的是一个半死的筛选组。 |
| **一类机会，不分轨道**：所有条目同一个列表；有没有动作由 `steps` 说话，没有步骤的卡标「仅观察」，`novelty` 说明它新在哪。 | 按「有没有动作」分两个 tab 会把新协议的活动藏进另一个列表，96 对 5 也说明这个二分没有信息量。 |
| **顶栏是 报告 / 设定**（2026-10-19, user）：报告是列表，设定是旋钮（字段由后端给，前端不认识任何一个键）。报告没有列表 tab：默认就是全部；**归档 / 删除** 收进左侧「已处理」组（全部 + 两行、带计数，再点一次当前行回到列表），**排队中**由左侧「队列」组进入。轮次由报告页的日期 stepper 翻，设定页没有。 | 与雷达顶栏同一条写法；把设定塞进面板会让"这一页在筛什么"和"这一页在改什么"混在一起。 |
| **设定页是 ARC 同款分块**（2026-10-21）：采集 / 分析 / 查询与闸三块，每块一张分组卡；参数名简短，完整解释在卡片右上「说明」浮层；修改后顶部出现 `.dirtybar`（参数已改 N 项），保存成功后消失。 | 9 个参数平铺成表格会把「采集 / 分析 / 查询」的关系抹掉，长解释常驻又淹没参数。 |
| **报告 / 设定是这一页的记忆**：当前选择存 `ch.opportunity.view`，切左栏或刷新后回到上次那一面；轮次不存。 | 每次回到新机会都跳报告，读者在设定页来回切时会丢掉位置。 |
| **轮次条只在报告页**：位于 报告 / 设定 下面一行，复用雷达的 `.bhead`（`‹ 日期 ›` + 出卡数）；左右箭头翻历史，后面紧跟「全部轮次」与「回到本轮」——两个跳转做成与列表同一套分段 tab（选中态蓝底），始终可见，跟在出卡数后面。宽度不随轮数增长。选中一轮后，左侧状态与排队中的计数都按那一轮重数（帖子按采集它的轮次归属；全部轮次时是全局累计）。设定页没有轮次。 | 条带一多就横向溢出；日期 stepper 和雷达是同一种动作、同一个宽度。计数不跟着轮次走，就会出现「11 张卡、左边写着 80」。 |
| **归档 / 删除是读者自己的决定**，与管线的 `status` 分两列：卡片页脚右端两个图标按钮；进入「已处理」后换成「恢复」。删除是软删。两者都**冻结**这张卡：抽取、补链、热度与生命周期都不再改写它，恢复后重新纳入。 | 一张卡可以同时是「未晋升」（管线）与「已归档」（你）；一列说不清两件事。 |
| **排队中的三堆在左侧「队列」组**：只列非零项；点哪一类就只渲染那一段，并保留当前选中的轮次。切到生态 / 状态 / 已处理分组时回到列表。三堆都完整列出（`limit=0`），不再只给前几条。 | 排队中的东西信息量与卡片差一个量级，混在列表末尾会让列表忽长忽短；把计数放回面板又会让「这一轮做了什么」和「还剩什么」混成一条。 |
| **一个列表 + 一个面板**（2026-10-18, user）：`fav-side` 占内容区第一列（320px，与 收藏 / 搜索 同一条轨道规则 `#view-… .fav-body`），卡片区 `fav-cards` 在第二列起。**状态筛选取代了原来的两个折叠区**：未晋升与已结束是同一批行从另一面看，同一行出现在两处，页面就开始跟自己不一致。 | 混成一个列表而**没有**状态筛选，「为什么这个没上列表」就没人能回答；而两个折叠区与两个列表并排，等于同一批数据维护两份渲染。 |
| **面板由后端给**：哪些分组存在、每个选项叫什么、有哪几个排序键，全在那一次读取里（`filters` / `sorts`），前端不识别任何一条。**只有真有两个取值的分组才出现**（一个只能把页面筛空的开关，是这个应用不出的那种控件）。 | 前端硬编码类目表，后端加一个类目就要改两处；把只有一种取值的分组也画出来，读者点下去只会得到空页。 |
| **计数只在 状态 那一组**（可参与 / 未晋升 / 已结束），它原来是页头那一行；其余分组不带计数（与 收藏 / 搜索 的面板一致）。 | 每个选项都带计数会让人以为它忽略其他筛选，而那些数字只在状态这一组是完整读数。 |
| **排序两个键**：发现时间（默认，各来源一致的那个）与截止时间（材料抄来的事实，没有截止的排最后，两个方向都一样）。**热度不在其中** —— 它是来源帖自己的读数，只做徽章与筛选。方向永远两行、随排序换文案，面板高度不变。 | 拿热度当排序键，等于让"谁被看见"取决于我们读了哪些号；没有截止时间的按 0 参与比较，会把它们排成"最早截止"。 |
| **筛选与排序在前端做**（`useMemo`）：这一次读取本来就是"一次给全页"，与 收藏 / 搜索 同一套分工；输入框（标题 / 账号 / 类目）边打边筛，不落库也不记进 `prefs`。 | 每改一次筛选就打一次后端，等于给一个已经拿到手的列表加一次网络往返。 |
| **卡片是条目自己的形状**，不复用报告卡：活动要列步骤（每步只留一个来源图标），项目只要一句「是什么」。标题行的类目与新机制同词时只画一次；元信息行只放热度 / 核实 / `@账号`（链到 X 主页）/ 官方入口，发现 / 开始 / 截止**单独一行**；门槛行贴在页脚正上方，页脚只留「原文」与归档 / 删除（在已处理桶里是「恢复」）；没有门槛信息写成灰字，不画成 chip。 | 复用报告卡就要回答「分数是多少」——条目没有分数，也不该有。同一件事在标题、徽章、页脚各说一遍，卡片看起来就是乱的。 |
| **同排等高，但单卡展开只长它自己**：网格默认 `align-items:stretch`，折叠态与批量展开态同一排等高（批量展开以最高的那张为准）；只有当某张卡自己按了「展开」（`.opp-body-wrap.single`）时才切到 `align-items:start`，让那一张变高而邻居不动（2026-10-24, user）。 | 一直用 stretch，单卡展开会把整排拉到同样高度，看起来像"所有卡片都展开了"；一直用 start，折叠态与批量展开态又会长短不齐。 |
| **门槛行永远在**：抽不到门槛显示「门槛 未判定」。 | 未判定是这个模块自己的一个读数（与热度的未判定同一套说法），不是"这条没有门槛"；顺带它也让折叠态的卡片少一处高度差。 |
| **整张卡只有一块是可变高度**：正文（一句「是什么」+ 步骤 + 风险）固定 7 行（`--opp-body-lines`），其余每一块都固定 —— 标题、徽章行、门槛行（超两个显示 `+N`，全集在 tooltip）、原因行、页脚。**这是报告卡的原话**（`Card.tsx` 的注释：折叠时每块都固定、只留一块可变），照搬它，卡片才等高（实测：折叠态正文一律 151px）。 | 第一版有五个可变块（正文、步骤、门槛、风险、原因），于是每一行的高度都不一样 —— 一屏卡片看起来就是乱的（user, 2026-10-18）。 |
| **「展开」只在真被截断时出现**（`scrollHeight > clientHeight` 实测，`ResizeObserver` 重测），展开时跳过测量。正文行高统一为 `--opp-line`（21.5px）、块之间不留垂直 gap，所以固定 7 行正好切在行边界上，不会露出半行；按钮仍在右下角，与币卡一致。 | 按字数猜会在边界上时有时无；行高不一致会让 7 行的框切在半行上，文字从按钮下面漏出来。 |
| **顶栏的 `展开卡片` / `收起卡片`**：一次落到每一张卡上（批量时取消固定高度），卡片自己那个「展开」按到下一次批量动作为止。图标沿用雷达 / 收藏 / 搜索三页的 `UnfoldVertical` / `FoldVertical`。**展开状态不记住**：刷新回到折叠。 | 批量展开之后还留一个要点一下的块，等于"全部展开"没做完；把展开状态持久化，则与雷达（不记）不一致。 |
| **trust 三态、只做徽章**：官方 / 社区 / 未判定。未判定是**一个读数**，不是缺失，所以它既不被藏起来也不被合并进社区；筛选组仍只有生态与状态。 | 两态（官方 / 社区核实中）会把「我们没查」混进第二态，而这一页的价值恰恰在于说清每条是谁说的。 |
| **顶栏是一行，但新机会分两态**：报告页 `运行结果 / 展开卡片 / 搜索框`，设定页 `运行结果 / 保存并生效 / 立即运行`；`中止` 不在顶栏，它在运行面板的标题行里（与 Arc 一轮同一位置）。用 `.topbar` / `.acts`，不是收藏页的 `.fav-bar` / `.fav-tools`；报告页搜索框仍是同一个 `.fav-search`（322px）。 | 报告与设定需要的动作不同；把两套同时摆出来，读者分不清哪个属于当前页。用收藏页的 `.fav-bar` 会让底线的内缩与雷达不一致（2026-10-21 修过）。 |
| **meta 行与时间行分开**：meta 行是热度、trust、`@账号` 与官方入口，整组一起换行；时间行单独显示发现 / 开始 / 截止。语气用既有的 `.pill-<tone>`（`pillClass()` 组装，`pill warn` 不是类）。 | 徽章放标题行会在长标题处换行成"第二个标题"；把时间塞进 meta 行会让账号与日期挤成一团，读者很难先看到「什么时候」。 |
| **不在列表上的条目自己说明为什么**：原因写在时间行的下一行，`未晋升 · …` / `已结束 · …`，跟状态在一起，不跟页脚的操作挤在一起；内部代码由 `promote.REASONS` 译成中文（`offchain` → 不在链上）。 | 只画成功的那些，「为什么这个没上列表」就没人能回答；而门槛的每一次拒绝都记了原因，不画出来等于白记。 |
| **watchlist 只读**：折叠区里列出扫描会读的源（账号与查询两类，查询行带自己的窗口 / 片长）与验证说明。**没有增删按钮** —— 这一版没有写接口。 | 「一个静默的空开关比缺少一个旋钮更糟」：按不动的按钮比没有按钮更坏。 |
| **扫描复用一轮的面板**（`rp-*` / `rst` 与同一个 Marker）：七个阶段各自记 state 与秒数，**运行中的阶段还画阶段内进度**（`6/40`、`33/60`，来自 `stage.done` / `stage.total`），段内读数取自扫描行的计数（读了几个源、过闸几条、分了几组 / 无关 / 待定、落了几个条目、补上几条链、退休几条）。分组的读数是 `分组 N · 无关 N · 待定 N`；补链的读数是 `待补 N · 补上 N · 搜索 N`。它不是逐帖问答的「问了几条」。**中止在面板标题行右侧**，与 Arc 一轮同一套：两段式确认（`确认中止`，10 秒窗口），确认后换成不可点的 `正在中止` 直到扫描离开 running，状态写 `已中止 · 本次`。 | 另造一套阶段面板，两边「失败停在哪」很快就会不一致；把中止放在顶栏，按钮会跟 POST 的 pending 走，POST 毫秒级回来就显得没生效。 |
| **一次只跑一个扫描**：按钮在扫描进行中禁用并显示「扫描中…」；后端的 409 原文照打。页面按 `scan.status === "running"` 决定轮询（1.5s），扫完即停。**扫描中面板标题行多一个「中止」**：它停在下一次 X 调用上（后端的旗子每 100ms 轮询一次），而扫描通常卡在限流上 —— 等这一次调用回来等于让读者再等四十秒。 | 靠按钮禁用而不处理后端的拒绝，多开一个标签页就会撞 409 而页面不知道为什么。 |

## 中止一轮

中止是在进程内存中立起的一面旗，不是回滚：轮次停在哪个阶段就是哪个阶段，不写出任何一张报告。

| 规则 | 说明 / 反例 |
| --- | --- |
| 口径是**只在进程内存里立一面旗**（`api/app/cancel.py`）：`POST /runs/{id}/cancel` 立刻返回 —— 一轮跑在 `schedule.py` 的单线程 worker 上，HTTP 处理器够不到那个线程；轮次自己在下一个检查点读旗、抛 `RoundCancelled`。 | 旗按 run id 存、轮次结束就清 —— 写进数据库的话，重启后上一轮的停止请求还在，下一轮会继承。 |
| 一轮没有回滚可做：落库只有最后一笔事务（`store_round` ＋ `store_reports`），停在哪个阶段就停在哪个阶段，**不写出任何一张报告**。 | 另建一套回滚机制，复杂度会花在不需要的地方。 |
| 检查点只用轮次本来就有的边界，**没为中止新增计时器或线程**：源之间、阶段边界、补齐与富集池里**每个币开跑之前**（`http.pmap` 的 `stop`）、`_gate` 的每个标的、每个币的词条之间、一次调用的前 / 后与读响应体的每一块之间。 | 加一个每秒轮询的计时器只会多一个线程，还让每轮变慢。`pmap` 在「下一个任务开跑前」问，**在途的那几个必须跑完才算停**，所以响应时间是一个币的一次网络等待：秒级，X 搜索那一步按其自身的 120s 子进程超时计算。**不应承诺「点击立刻停」**。 |
| 在途的模型答案可以放弃，但**不能退化成 `LLMUnavailable`**：`client.stream` 按块查旗，命中就关连接抛 `RoundCancelled`；关键是 `complete()` 里单开 `except cancel.RoundCancelled: raise`。 | 退化的话，一轮会用「没写词条」的样子把报告发出去。 |
| 旗只从 `cancel.check(run_id)` 进线程池，**不在任务函数里抛**：在途的任务请求**已经发出去了**，线程从外面杀不掉，只能等它自己返回（这就是「在途必须跑完」）；而任务里抛会被 `pmap` 读成「这个源什么都没答」（`None`），一轮就会带着半池数据继续跑。行里没有 run id 的调用（CA 搜索）拿到的是**空检查**，永远不停。 | 反过来写，一次中止会伪装成一次网络失败；给不是轮次的搜索也配一个能停的旗，界面就得给它一颗停不下来的「中止」。 |
| 两个例外：排队中的那一轮尚未开始运行，因此读不到旗，由路由直接落库（`run.stop_run`）；写库之后不再有检查点，停止请求晚到则照常发布。 | 只立旗的话，排队中的那一轮永远不会停；在事务里插检查点，报告就会部分写入 —— 已发布的报告不该被改写成「已中止」。 |
| 前端把中止当跑完处理：`已中止 · 本轮`，步骤列表照常显示（已结束的有耗时，没走到的画 `—`）；**新状态 `cancelled`** 进 `states.TERMINAL`。按下确认后按钮**留在「正在中止」**直到这一行离开 live，**不跟着那次 POST 的 pending 走**（POST 毫秒级，轮次是秒级）；双击窗口 10 秒。顶栏开关的**收起那一半**退回**最近一轮有卡的批次**，**展开那一半不改变用户所在的位置**，刷新同理。 | 记成 `failed` 会让「失败率」虚高；刷新后跳回那个没有结果的批次即由此产生。POST 回来就把「中止」递回去，操作者会以为没生效而重复点，或以为停不下来。 |

## 数值显示

数字的写法只有一处出口，页面不自己格式化。

| 规则 | 说明 / 反例 |
| --- | --- |
| 分数只输出整数：库里和接口里带一位小数（打分条要用这个小数画长度），**页面显示值一律四舍五入到整数**，出口只有 `web/src/format.ts` 的 `whole()`。**四舍五入是半进位**：Python 的 `round()` 是半偶进位，两边不应混用，所以 Python 侧写 `math.floor(x + 0.5)`。 | `toFixed(1)` 是反例 —— 同一个分数的两种写法出现在同一屏内，会被读成两套数字。 |

## 为什么这么定

每一条都是由一个具体的错误纠正出来的；现行口径见右列。

| 曾经的错 | 现在写在哪 |
| --- | --- |
| 链下调研的外链只从 `snapshots` 读取 → 一个从未被补齐过的 CA 必然判为「没有可读的外链」，写作整段不执行 | 本文件 · CA 搜索 |
| 中止只在阶段边界读旗 → 补齐那一段（逐币补全池）一个检查点都没有，点中止看起来没反应，最坏要等它跑完 | 本文件 · 中止一轮 |
| 「正在中止」曾跟着那次 POST 的 pending 走 → POST 毫秒级就回来了，按钮立刻变回「中止」而轮次还在跑，操作者以为没生效而重复点 | 本文件 · 中止一轮 |
