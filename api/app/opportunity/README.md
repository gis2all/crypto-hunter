# 新机会：外部活动与新项目的发现

这份文件是该模块的 README（仓库约定：每个大模块一份）：前面是设计与口径，末尾是落地后的实现形状。

这个模块只干一件事：**从外部世界发现两类东西，把它们变成带来源、可核实的条目。**

- **可参与活动**：有人能做一件具体的事（打新 / 挖矿 / 做任务 / 空投 / 测试网 / Mint / 白名单 / AMA）。
- **新项目 / 新协议 / 新实验**：出现了一个值得看的东西（协议、工具、标准、实验），**未必有可参与的动作**。

它不读代币筛选流水线的任何产物（候选池、分数、快照），也不参与排名；一条条目是否存在，与「我们有没有筛到某个币」无关。

## 一类机会，两种读法

所有条目在同一张列表里，不再按「可参与 / 发现」分轨道。判据仍然是 1–5 机会族加动作短语；
新协议 / 新玩法 / 新机制走 `discovery-words` 过闸，进来后同样是一张普通卡。**有没有动作由
`steps` 说话**：没有步骤的卡在页面上标「仅观察」，`novelty` 说明它新在哪。

CEX 交易所营销账号排除；BSC/BNB Chain 等链生态保留。family 6（Grant / 黑客松 / Bounty / 开发者任务）本阶段不做。

## 定位

| 规则 | 说明 / 反例 |
| --- | --- |
| 「机会」是**外部世界发生的事**，不是代币：判据是「有人能做一件具体的事」或「出现了一个新东西」，而不是「有个币值得看」。 | 反例：把筛选出来的候选币当成机会 —— 那是雷达页已经有的东西（user, 2026-10-18）。 |
| **两类东西，两种门槛**：活动要求「有步骤」，新项目/协议不要求（它常常还没有任何可参与的动作）。 | 用一条门槛盖两类，会把「新协议」整类挡掉；参考产品为此专门留了 `hasConcreteActivity` 与一段降级文案。 |
| 与代币流水线**零耦合**：不读 `run_items` / `snapshots` / 候选池，不写 `runs`，不参与打分与分位。 | 一旦读候选池，条目的多少就变成「这一轮筛得多深」的函数，而它本该是「外面发生了什么」的函数。 |
| 一个模块，自己的词汇：watchlist / 帖子 / 分组 / 抽取 / 晋升 / 核实。这些词不属于 `sources/`（产出 `TokenMetrics`）、`report/`（以一轮为单位）、`search/`（以 CA 为输入）。 | 塞进任一个，那个模块就要长出第二套语言，`lookup.py` 当初独立出来就是这个理由。 |

## 两类东西

| | 可参与活动 | 新项目 / 新协议 / 新实验 |
| --- | --- | --- |
| 判据 | 有人能做一件具体的事，**有步骤** | 出现了一个东西，**说得清它是什么** |
| 时间语义 | 窗口：开始 / 截止 / 进行中 | 首次出现 + 最新动态（官方号最后一帖） |
| 类目 | 打新 / 挖矿 / 做任务 / 空投 / 测试网 / Mint / 白名单 / AMA / 其他 | 新协议 / 新实验 / 新工具 / 新标准 / 基础设施 / 其他 |
| 门槛 | 步骤 + 官方入口 | 官方入口 + 一句「是什么」 |
| 门槛之外的字段 | `barrier`（八档）必填（抽不到＝未判定） | `maturity`（实验性 / 测试网 / 主网 / 未判定） |
| 列表 | 同一个列表（按卡片内容渲染） | 同一个列表（按卡片内容渲染） |

| 规则 | 说明 / 反例 |
| --- | --- |
| 两类共用一张表、靠 `kind` 区分（`activity` / `project`）。 | 拆两张表，`trust` / 证据 / 扫描三套逻辑就要各写两遍，而它们说的是同一件事。 |
| 「新实验」不是第三个 kind，而是项目类目下的一个类目 + `maturity = 实验性`。 | 实验与协议的区别是成熟度与是否可参与，不是另一套流程。 |

## 类目

活动类目（`kind = activity`）：

| 类目 | 判据（用户能做什么） | 第一传感器 | 门槛的典型值 | 时间语义 |
| --- | --- | --- | --- | --- |
| 打新 | 在窗口里认购 / 申购 / 存入，换新币或份额 | 交易所官方号 + 发射台官方号（X） | 需资金、需持仓、需 KYC | 有明确窗口 |
| 挖矿 | 跑节点 / 挂机 / 浏览器挖 / 质押 LP，按算力或时长产出 | 项目官方号 + 官方文档 | 需 gas、需设备或挂机、需锁仓 | 多为进行中，常无截止 |
| 节点 | 跑验证者 / 节点 / sequencer / prover，或买节点、委托节点 | 官方文档 + 节点销售页 | 需 VPS、需质押、需设备或挂机 | 多为长期，有申请窗口 |
| 做任务 | 按清单完成社交 / 链上动作，领积分或白名单 | 任务平台列表页 | 需钱包、需 gas、需社交账号、需邀请码 | 多为活动期，有截止 |
| 交互 | 在已有协议上做链上动作（swap / bridge / LP / 签到），换积分或潜在空投 | 项目官方号 + 官方文档 | 需 gas、需资金 | 常无截止 |
| 空投 / 领取 | 已符合资格，去 claim | 官方号、任务平台 | 需资格（快照）、需 gas | 有领取窗口 |
| 测试网 / 公测 | 试用产品、反馈、攒积分 | 官方号、查询清单（X） | 需水龙头、需设备 | 常无截止 |
| Mint | 免费 / 付费铸造 | 官方号、市场 | 需资金、需白名单、限量 | 有开铸时刻 |
| 白名单 | 报名 / 抽签进名单 | 官方号、社区（TG / Discord）、任务平台 | 需社交任务、需邀请 | 有报名截止 |
| 治理 | 投票 / 委托 / ve 锁仓 / gauge / 提案 | 官方治理论坛、官方号 | 需持仓、需质押 | 按提案周期 |
| AMA / Spaces | 参加线上活动（常给 POAP / 白名单） | 官方号 | 无 | 有具体时刻 |
| 其他 | 兜底 | 关键词扫描 | —— | —— |

项目类目（`kind = project`）：`新协议` / `新实验` / `新工具` / `新标准`（资产标准一类，如铭文、Alkanes 那种） / `基础设施` / `其他`，外加 `maturity ∈ 实验性 / 测试网 / 主网 / 未判定`。

### 大类（category_group，2026-10-26）

面板的第一组筛选是 `category` 的上一层读法，由 `schema.category_group_for()` 在读取时派生，
不进库。字段名是 `category_group`，**不要和 watchlist 的 `family`（查询的 1–5 机会族）混淆**：


| 大类 | 归入的细类 |
| --- | --- |
| Mint / 挖矿 / 打新（投入型）`invest` | Mint、挖矿、打新 |
| 节点 / 验证（投入型）`node` | 节点 |
| 空投 / 白名单（资格型）`qualify` | 空投、白名单 |
| 测试网 / 做任务 / 交互 / 治理（参与型）`engage` | 测试网、做任务、交互、治理 |
| 新协议 / 新实验（观察型）`protocol` | 新协议、新实验 |
| 新工具 / 基础设施 / 新标准（观察型）`tooling` | 新工具、基础设施、新标准 |
| 其他 `other` | AMA、活动「其他」、项目「其他」、词表外的细类 |

`治理` 目前只有一张卡，先并进参与型；等它长到两位数再单独成行。

细类本身由抽取写入（`prompts/extract.md` / `extract.md@3` 起有 `节点 / 交互 / 治理` 的判据）。

只改 `category`，说不清就留在「其他」。2026-10-26 回填 76 张，改掉 44 张。

## 发现（Discovery）

**X 是单一来源**（2026-10-18 起）：`official` 账号的时间线，以及 `query` 分类查询。查询只产出候选帖子，不判定事实；免费闸与分组在扫描里完成。平台页、交易所公告、目录与 GitHub 读取器已移除，名单留在种子 `pending:` 段。

### 生态（面板的主轴）

`schema.CHAINS` 是已知链；不在表里的公链保留它自己，存小写键。

| 规则 | 说明 / 反例 |
| --- | --- |
| **列存键，面板印名**（2026-10-24, user）。 | `tron` 存键、显示 `Tron`；`bttc` 显示 `BTTC`；`multiversx` 显示 `MultiversX`。显示名在 `ECOSYSTEM_LABELS`，筛选值始终是键，所以同一链不会长出两行。 |
| **生态从材料读出来**，不是从"谁发的帖"继承（2026-10-19, user）。 | 一个 Solana 账号宣布 Base 上的项目，条目就该写 `base`。继承来源行会把"项目在哪条链上"变成"我们在哪儿看到它"，那是两个问题。 |
| **已知链走别名表**（`Ethereum`、`eth`、`以太坊` 都归 `ethereum`）；枚举外的真链保留自己，统一转小写。 | 自由文本会让面板每加一种拼法就多一行 —— 而面板那一组是读者浏览的轴。`Tron` 与 `tron` 不能是两行。 |
| **`多链` 与 `未判定` 是两件事**：前者是"材料说它同时在好几条链上"，后者是"材料没说"。 | 它们 2026-10-19 之前是同一个值 `multi`，而那个值在种子里实际表示的是"我不知道"。 |
| **抽完之后统一补链**（2026-10-24）：卡片标题与摘要里只点名一条链就直接用；否则读溯源页；再否则每个项目一次网页搜索（Exa 公共 MCP，失败换 Parallel），最后才让模型在给出的结果里选。 | 搜索结果页在本机会被代理换内容，MCP 在厂商服务器上搜，绕开这一层。模型必须给出结果里的 `url` 作为证据，没证据就留 `未判定`。 |
| 老的首字母大写值一次性回填成键（`Tron` → `tron`，`Multi` → `多链`，2026-10-24）。 | 回填前 8 行是 `Tron` / `Flare` / `Bttc` 这类显示名；不回填的话，新写的 `tron` 会和老行并存。 |

## 分组与抽取（Group / Extract）

| 规则 | 说明 / 反例 |
| --- | --- |
| 把**一批**过闸帖一次交给模型分组：每条正文完整发送、不截断；模型只回项目组、无关、待定三桶，不写摘要，也不逐帖问答。 | 逐帖分类把一个项目拆成十几通电话，既慢又让同一项目的帖子在队列里互相看不见；分组一次就能把它们放在同一段上下文里。 |
| 一轮尽可能覆盖全部待分组帖：主调用后若仍有缺失或待定，只对这部分做补充调用，最多两次；两次后仍无法归组的写 `classified = 'other'`（不建卡），整批继续落库。只有模型调用或 JSON 本身失败才让整站失败。 | 一条模糊帖子不该卡住整批；但模型漏 id 与模型明确说"不确定"仍要计数，不能伪装成"无关"。 |
| 分组帖子上限默认 1000，是硬上限而不是分页大小：待分组数超过上限直接报错，不拆批、不先写一部分。 | 上限只用来防一次调用失控，不承担"分批处理"的职责；先写一半再报错，等于把失败伪装成成功。 |
| 每个 id 必须且只能落进一个桶；同一 id 出现在多个组时归第一组。组按 handle 优先、再按 `topic.normalise(name)` 合并，空组、无组名与非法 `kind` 丢弃。 | 重复归属会让同一项目出现两张卡；不合并同一 handle 的多个组，则一个项目会被模型拆成几份。 |
| 活动抽取**带来源的参与步骤**：标题、主办方官方号、官方入口、步骤（每步 `title` / `body` / `source{url, at}`）、`barrier`、风险。 | 步骤不带来源，等于让模型凭印象写参与方式 —— 这个模块最不能出的错。 |
| 项目抽取**一句「是什么」**：标题、官方号、官网 / 文档 / 仓库、`category`、`maturity`、风险；**不要求步骤**。 | 新协议常常还没有可参与的动作；要求步骤就只剩"关注官方公告"一句话可写。 |
| 铁律与写手同源：**只写页面 / 帖子上真实出现的东西**；数字写出来；抽不到写空，**不许推断**。 | 沿用 `report/prompts/research.md` 的写法纪律，不另立一套。 |
| 校验失败**先重问一次**再降级；降级 ＝ 这条不晋升，而不是"写一段像样的文字顶上"。 | 与 `report/README.md` · 词条文字同一套机制（校验器原文回传 + `REPAIR_HEAD`）。 |
| 抽取结果带 `extract_version`（prompt 版本）。 | 参考产品的唯一痕迹是 `howToOfficial.at`；没有版本，规则升级后旧条目就成了无出处的断言。 |

### 门槛枚举（活动类）

`barrier` 固定八档、**可多选**，抽不到就是 `unjudged`，**绝不写「无门槛」**：
`无成本` / `需 gas` / `需资金` / `需质押` / `需白名单` / `需 KYC` / `需设备或挂机` / `需社交任务`。

| 规则 | 说明 / 反例 |
| --- | --- |
| 门槛必须枚举化。 | 参考产品的 `barrier` 是自由文本（`无白名单 · 主网 · 需兼容钱包`）：好看，但没法筛选、没法比较，而"这条要不要动手"恰恰取决于门槛。 |

## 核实（Verify）

`trust` **三态**：`official` / `community` / `unjudged`。

| 规则 | 说明 / 反例 |
| --- | --- |
| `official` 只在**官方自己说过**时成立：条目出现在官方号自己的帖子里，或官方站点 / 文档里写了它。 | 参考产品只有「官方 / 社区核实中」两态，把"我们压根没查"混进了第二态。 |
| 只在社区账号、KOL、第三方目录里出现 → `community`；**没查到 → `unjudged`**，且必须在页面上看得见。 | 「缺值只会是未知，不会变成放行」：`unjudged` 不是"大概是真的"，也不是"假的"。 |
| 判定复用 `search/identify.py` 的原语（`mentions` / `host_of` / `AGGREGATORS`），不重写一套域名与页面判断。 | 两套判断会漂移，而漂移的方向恰好是"把聚合站当成官网"。 |
| 新实验 / 新协议的 `trust` 更要紧：一个人的玩具与一个团队的协议，页面形状可以一模一样。 | 没有三态，实验性项目会被默认读成"官方"。 |

## 晋升（Promote）

| 规则 | 说明 / 反例 |
| --- | --- |
| 活动晋升：**至少一条步骤** 且 **有官方入口**。项目晋升：**有官方入口** 且 **有一句「是什么」**。两者缺一，进「未晋升池」并记原因。 | 参考产品的前端过滤是 `hasConcreteActivity !== false && howToSummary.length > 0` —— 门槛对，但它不留痕。 |
| 未晋升原因：`no_steps` / `no_official_link` / `no_summary` / `not_classified` / `unread`。 | 原因要能对上页面上的行，否则调参只能靠猜。 |
| 未晋升**不是淘汰**：它是"这次没成"，记原因、可查、下一轮可以再晋升。 | 「未判定永不淘汰」在这里的形态是「未晋升不删除」；把未晋升写成 `not_an_opportunity` 就是把沉默当成了结论。 |
| 未晋升池在页面上可见（对标雷达页的落选池）。 | 「不可观测即不可复核」。 |

## 数据模型

五张表，全部进 `store/schema.sql`（数据模型的唯一出处），加列走 `db.init_db` 的 `_ADDED_COLUMNS`。

| 表 | 主键 | 性质 | 存什么 |
| --- | --- | --- | --- |
| `opportunity_sources` | `id` | **可编辑**（操作者随时加账号 / 查询） | watchlist：`target` / `kind`（`official` / `query`）/ `ecosystem` / `cluster` / `enabled` / `window_hours` / `slice_hours` / `max_results` / `note` / `added_at` / `last_read_at` |
| `opportunity_posts` | `tweet_id` | **只增不改**（原始事实） | 帖子原文与 `metrics_json`、`posted_at`、`url`、`source_target`、`score` / `rules_json`（免费闸的读数）、`project_name` / `project_handle` / `project_urls_json`、`trace_level` / `trace_json`、`classified`、`extracted_at` |
| `opportunities` | `slug` | **可编辑**（重抽 / 人工修订） | `kind`（内部读数） / `category` / `title` / `organizer` / `official_url` / `summary` / `trust` / `trust_basis` / **`ecosystem`（材料读出来的链）** / `ecosystem_checked_at`（补链问过的时刻，NULL = 还欠一次） / `source_type`（我们怎么找到它的） / `risk` / `barrier` / `maturity` / `started_at` / `deadline` / `status` / `reason` / `heat` / `heat_basis` / `discovered_at` / `source_kind` / `source_ref` / `extract_version` |
| `opportunity_steps` | `(slug, ordinal)` | 随条目一起重写 | 每一步：`title` / `body` / `source_url` / `source_at`（活动类才有行） |
| `opportunity_scans` | `id` | 只增（回执，对标 `search_jobs`） | `status` / `stage` / `stages_json` / `counters_json` / `started_at` / `finished_at` / `error` |

| 规则 | 说明 / 反例 |
| --- | --- |
| `opportunities.status ∈ candidate / promoted / retired`，**未晋升的行也留在这张表里**，靠 `reason` 说明为什么。 | 拆成两张表就要同步两处，而它们说的是同一件事。 |
| `discovered_at` 是**本项目第一次看到它的扫描时刻**，不是帖子发布时间、也不是官方宣称的开始时间。 | 三个时间各有出处：`discovered_at` 用于排序（口径一致），`started_at` / `deadline` 只从原文抽。 |
| `deadline` 抽不到就是 `null`，**永不推断**。 | 参考产品 126 条项目里 `deadline` 填充 **0 条** —— 没有规则时，"截止时间"就是编出来的。 |
| 表**不带 `config_id`**：同一条目不该因为换了一套设定就分成两条。 | 与 `favorites` 同一取舍；与 `lexicon` 相反（词条是"这套设定这一轮的判断"）。 |
| watchlist 的**出厂种子**在 `opportunity/seeds/watchlist.yaml`（跟仓库），首次运行播种进 `opportunity_sources`，之后以表为准。 | 与 `config/chains/*.example.yaml` → `<id>.yaml` 同一套做法：模板跟仓库，运行时那份在库里、可编辑。种子里每个 handle 都验证过存在，没验证的进 `pending:` 段而不入库。 |
| **不建 CA 关联键**（user, 2026-10-18）。将来要挂钩，加一列即可。 | 现在挂钩，条目的读法就要跟着代币的读法走，两个模块的节奏也就绑在一起了。 |

## 运行方式

| 规则 | 说明 / 反例 |
| --- | --- |
| 独立 job，**不进 `pipeline/`、不写 `runs`**：模块自带单线程池 + `opportunity_scans` 行，对标 `lookup.py`。 | 塞进一轮的编排，就要么被 4 小时节奏绑住，要么给 `runs` 表加第二种行。 |
| 节奏独立于链的排程：先手动触发，稳定后再谈定时。 | 一个还没跑通的流水线先挂上定时，只会每小时制造一批没人看的行。 |
| **一次扫描读不满整份 watchlist**：按 `last_read_at` 最久没读过的先读，取前 `MAX_SOURCES`（40）个，剩下的记进 `counters.deferred`。 | 一份 127 行的 watchlist 全读一遍是五分钟的节流睡眠加一次限流；而"每次都从头读"会让尾巴永远读不到。上限必须写成轮转，且被推迟的数量要看得见 —— 否则"轮转"会被读成"覆盖"。 |
| 每个源读过就读写 `last_read_at`，**失败的源同样算读过**。 | 失败的那个正是下一轮该再试的，把它留在队首就是再试。 |
| **本模块自带 X 调用节流**（子进程级别的串行 / 间隔），不复用 `http.MIN_INTERVAL`。 | X 走 subprocess 不走 `http.get`，那张表对它是空的；而调研阶段是 15 并发、一个币最多两次查询，两边同时打同一个账号就是封号路径。间隔是实测定的：2.5 秒时第 13 个连续时间线开始 429，而 CLI 自己的退避（5.7s → 11.4s → 21.8s）把每个失败变成四十秒 —— **慢一点的间隔反而让整轮更快**，所以现在是 5 秒。 |
| 平台与公告页抓取走 `http.get` 的既有节流与缓存（它们的 host 要进 `MIN_INTERVAL`）。 | 平台页是 HTML，抓取频率由节流表决定，不另立一套。 |
| 扫描要留下"这一轮用的是哪一版 watchlist"。 | watchlist 是可编辑的表，不记版本，"为什么这条被判成官方"就少了一个可回放的锚点。 |

## 落地形状

| 件 | 位置 | 说明 |
| --- | --- | --- |
| 免费闸 | `rules.py` + `seeds/rules.json` | 规则引擎：资格 / 加分 / 定档 / 硬排除，命中原因落在帖子上。**过闸靠资格规则，不靠总分**：只有具体动作短语（`run a node`、`deposit`、`complete quest`、`mint`）带 `qualify`；`validator`、`yield`、`lending` 这类名词只计 20 分，不能单独过闸。总分（`score >= 30`）只是下限与排序。硬排除覆盖 CEX、交易赛、CEX 活动号与理财、传统金融（信用卡 / 开户）、招聘、新闻观点、事故索赔、能力集成公告、非加密活动、订阅通知、互动抽奖、转发。发现机会要求官方来源 + 新东西描述 + 加密语境（链 / 代币 / 钱包 / 合约之一），否则 DuckDB 这类软件发布也会过闸。没过的记 `classified = 'skipped'`（不是 `other`），分数与命中规则一并留着。 |
| 一次分组 + 一次抽取 | `group.py` + `prompts/group.md`、`prompts/extract.md`（`extract.md@3`） | 分组一次覆盖全部待分组帖，完整正文不截断；缺失/待定最多补两次，仍有剩余的归 `other`。抽取仍按主题、按每轮预算执行。两次都记账进 `llm_calls`（`purpose` = `opportunity_group` / `opportunity_extract`）；抽取的 `prompt_version` 落进条目的 `extract_version`。 |
| 类目回填 | `recategorize.py` + `prompts/recategorize.md` | 一次性把已落库的「其他」重新读进闭集（`category` 只写这一列，说不清就留着）。不属于扫描，不建卡、不改摘要。 |
| 补链 | `chainsearch.py` + `probe.py` + `prompts/chain.md` | 抽取后统一处理仍是 `未判定` 的卡：卡片自己的字 → 溯源页 → Exa / Parallel 搜索 → 模型在给出的结果里选。链必须在引用的结果里出现；`not_onchain` 写 `retired` + `reason = offchain`。 |
| 一轮扫描要多久（实测 2026-10-18） | 42 次 X 调用 = **6.2 分钟**（每次约 9 秒：CLI 8–10 秒 ＋ 节流 5 秒，所以慢在**调用次数**上）；分组（离线 pilot，2026-10-21）390 条完整正文约 **15 秒**、93,455 prompt tokens；抽取按 **4 并发**跑，单个慢调用仍会拉长这一轮。 |
| 一次扫描的花费（含溯源，实测 2026-10-19） | 8 条溯源 × 约 1 分钟（1 次二次搜索 + 最多 3 个资料页 + 最多 2 个官网页）≈ 8 分钟，加在原来的 8.5 分钟上。二次搜索走时间切片但只有一片（问的是"现在谁在说这个名字"），它的 X 调用计入扫描的调用预算。 |
| 一次扫描的七个阶段 | `job.py` `STAGES` | 读 watchlist / 抓材料 / 分组 / 溯源 / 抽取与落库 / 补链 / 生命周期；阶段与计数写在扫描行上，页面轮询它。**可中止**：旗子在子进程循环里轮询，停在下一次 X 调用。 |
| **溯源接线** | `trace.py` + `settings.traces_per_scan`（默认 200，并发 4） + `extract._trace_of` | 扫描时只对**查询来源**的线索溯源（官方号来源本来就权威）；按项目去重，读候选 X、官网和文档页；**A 级账号自动进 watchlist**；A/B 的 `trust` 由溯源决定（A 官方 / B 社区·未互证），**C 级进未晋升池并写「未找到官方来源」**。抽取只处理已解析的主题；官方页随材料进提示词，官方 X / 官网 / 文档 / 原帖随卡片落库。 |
| X 读取器 | `xread.py` | 查询行的切片计划、一次请求一个子进程（带取消）、模块自己的节流（5 秒）。不复用 `XEngine.search` —— 那是按合约地址索引的筛币引擎，一条短语查询在它那里会**静默返回空**。 |
| 端到端读取 | `GET /api/v1/opportunity` | 条目（含步骤）+ 计数 + 最近一次扫描 + **筛选面板与排序键**（`filters` / `sorts`，后端建）+ 页面文案，一次给全：页面只读，不拼装、不判定。 |
| 阶段内的进度 | `job._tick` + `JobStageOut.done/total` | 一个六分钟的 collect 只写「running」两个字，页面看起来就是卡住了（user, 2026-10-18）—— 所以阶段行画 `6/40`、`33/60` 这样的读数。 |
| 卡片等高 | `#view-opportunity .fav-body .grid{align-items:stretch}` + 单张展开时的 `:has(.opp-body-wrap.single){align-items:start}` | 折叠态与顶栏批量展开态按行拉伸，同排卡片等高；单张卡自己展开时网格切成 `start`，只让那一张变高，邻居不动。门槛行永远在（抽不到写「门槛 未判定」），所以高度差只剩标题折行与原因行。 |
| 卡片的固定高度 | `--opp-body-lines:7`（`app.css`）+ `Body` 组件 | 整张卡只有正文一块可变（一句「是什么」+ 步骤 + 风险），其余每块固定；超出由右下角的「展开」打开，只在真被截断时出现。顶栏的 `展开卡片` / `收起卡片` 一次落到所有卡片。与报告卡的结论共用同一套类与按钮外观。 |
| 页面 | `web/src/features/opportunity/OpportunityView.tsx` | 一个列表 + 左侧筛选面板（`fav-side`，与 收藏 / 搜索 同一条轨道规则）+ 搜索框 + watchlist（只读）。卡片带步骤、门槛、热度徽章、来源与原文链接；不在列表上的条目在卡片底部写出原因。 |
| **设定** | `settings.py` + `config/opportunity.example.yaml` | 九个旋钮（读源 / X 调用 / 分组帖子上限 / 抽取项目上限 / 溯源项目上限、X 间隔、窗口、片长、过闸下限分）。 `form()` 返回 `fields` + 分块 `blocks` + `dirty_hint`；页面按采集 / 分析 / 查询与闸三块渲染，长解释在「说明」浮层。默认值写在代码里，`config/opportunity.yaml` **只存被改过的键**（设定页保存时创建），删掉即回默认。模块在调用处读 `settings.value(key, 常量)` —— 常量是默认值，所以测试仍可 monkeypatch，而设定文件不存在时什么都不改。 |
| **用户状态** | `opportunity_user_state` + `PATCH /opportunity/items/{slug}` | 归档 / 删除 / 恢复，与管线的 `status` **分两列**：一张卡可以同时是「未晋升」（管线说没找到官方来源）与「已归档」（读者说优先级不高）。删除是软删；**重抽永不撤销读者的决定**（upsert 不碰这两列）。归档或删除后这张卡**冻结**：抽取跳过、补链跳过、热度不重算、生命周期不改写；恢复后重新纳入。 |
| **页面 tab** | 报告 / 设定；报告没有列表 tab | 默认就是全部（除已处理之外的一切，含已结束）。左侧「已处理」组放全部 / 归档 / 删除（带计数、只在非零或选中时出现，再点一次当前行回到列表），进入后卡片页脚是「恢复」。排队中由左侧「队列」组进入，＝未分组 / 未抽取 / 溯源失败；那一组只列非零项，点哪一类就只渲染那一段，三堆都完整列出（`limit=0`），并保留当前选中的轮次（`scan` 参数；全部轮次时是全局累计）。轮次由报告页 报告 / 设定 下面的日期 stepper 翻（复用雷达的 `.bhead`，左右箭头 + 出卡数 + 全部轮次 + 回到本轮；后两个是分段 tab，选中态蓝底，始终可见）；设定页没有轮次条。 |
| 筛选面板 | `api/v1/forms.py` 的 `opportunity_filters` / `opportunity_sorts` | **后端给三组：大类（第一）、生态、状态**（2026-10-26, user）。大类的行名直接列出包含的细类（`Mint / 挖矿 / 打新（投入型）` …），顺序由 `schema.CATEGORY_GROUPS` 固定；生态按显示名的 A 到 Z 排，`多链` 与 `未判定` 最后。其后是前端加的「已处理」「队列」入口与「排序」。类别 / 核实 / 细类 / 门槛 / 热度 / 来源都**不是筛选组** —— 它们是卡片上的读数。**只有真有两个取值的分组才出现**；面板印显示名，筛选发键。**三组都带计数**，作用域跟着轮次 / tab / 搜索走：大类与生态各自排除自己那一维，状态跟着这两组的选择走。排序：发现时间（默认）与截止时间，热度不在其中。 |
| 热度 | `heat.py` | **热度＝来源帖自身的互动量**（浏览 ×1 / 赞 ×30 / 转 ×60 / 评 ×30），按 `log10` 折成 0-100，分档用参考产品那套词（极热 / 热 / 温 / 冷启动 / 静默）。刻度上限（`FULL_SCALE` 200 万）按实测最热的一条定（2026-10-18：Pumpfun 141 万浏览 → 98.4），超过即封顶 100。没有来源帖的材料是 `None`，页面写「未判定」；`0` 是一个读数（有人答了，答案是没人看）。刻度是派生的，所以**改刻度要重算**（`extract.refresh_heat`，在扫描的最后一个阶段跑）。 |
| 生命周期 | `lifecycle.py` | `deadline` **只从原文抽**（`extract.md` 的铁律），这里只负责读它：ISO / `YYYY/MM/DD` / `YYYY.MM.DD`，**只有日期时读到当天 23:59:59 UTC**（读成当天 0 点会把还活着的活动提前十二小时退休）。到点即 `retired`，`reason = deadline_passed`。**没有截止时间的一律不判结束**。 |

| 规则 | 说明 / 反例 |
| --- | --- |
| 热度**不是全站计数**，而且必须在页面上写明这一点。 | 本项目的 X 通道是一个 CLI，没有 `posts_counts_recent` 那类计数接口；拿"抽样命中数"冒名顶替，就是 `CLAUDE.md` · 边界与待决里「分位分母混口径」的翻版。所以口径写成"来源帖自身的互动量"，原始数字跟着分数一起显示。 |
| 热度**不做排序键**。 | 排序键应选各来源答案一致的那个：热度是一个来源自己报的数，换一批源就会变；本项目的 `discovered_at` 才是各来源一致的键。 |
| GitHub 走 `http.get`（节流 + 缓存一小时），不走 X 那条子进程道。 | 未认证的 GitHub API 每小时 60 次，而一次扫描会读好几个组织；不缓存就会把额度花在重复读同一份仓库列表上 —— 而仓库列表不像平台页那样分钟级变化。 |
| 生命周期只有两个可信来源：**材料写的截止时间**与**人来改**。 | 官方号沉默三周、页面 404、"看着像结束了"都不是答案；把沉默读成结束，就是拿"没问到"当结论。 |
| `retired` 只改状态，**不删行**。 | 一条结束的活动仍然是一个存在过的事实：它的步骤、来源与热度都留着，下一轮如果它复活（重新开放），同一 slug 会把它写回 `promoted`。 |

| 规则 | 说明 / 反例 |
| --- | --- |
| `source_ref` 存**材料的 URL**，不是行键。 | 读者点"原文"要落到那条帖子或那一页；"这一轮抽过没有"由 `extracted_at` 回答，不用这个列。 |
| **生态与来源类型随条目存下来**（`ecosystem` / `source_type`），而不是读时 join watchlist。 | 它们本来是来源行的字段；来源行以后被删或被改，条目仍该记得自己是从哪来的 —— 而页面要按它们筛选，读时 join 会让「筛不到」与「来源被删」变成同一件事。老行由 `_backfill_opportunity_sources` 一次补齐（三跳都是已存的事实，没有猜测）。 |
| 条目的 `discovered_at` **只在首次写入时定**，重抽不覆盖。 | 它是本项目的观测时间、也是列表的排序键；被重抽刷新一次，列表就变成了"最近被重抽的顺序"。 |
| watchlist **只读**地呈现在页面上；条目只有一个读者写动作：归档 / 删除 / 恢复（软状态，不改管线的 `status`）。 | 「一个静默的空开关比缺少一个旋钮更糟」：没有写接口，就不放一个按不动的按钮。 |

## 明确不做

- 交易、买卖点、仓位建议、实时行情（`CLAUDE.md` · 项目定位）。
- 社区功能：打分、留言、积分、任务中心、白名单 —— 参考产品有，但那是多用户，明确不在范围内。
- 推送：`out/` 保持占位；要不要接，先过产品定义再谈。
- 自动判定「已结束」：状态先只区分 `candidate / promoted / retired`，`retired` 由人或后续规则给，不由模型猜。
- 链上合约扫描：与代币流水线的边界太近，且"新协议"的第一传感器是目录与官方号，不是链。

## 溯源：线索 → 官方家（设计，2026-10-19, user；已落地）

**每条帖子只是一个线索**，不是一条条目。要让条目权威，它必须落到项目**自己的**官方来源上。
（这与"挖链"是同一件事，但挖链是按**合约地址**证明的，机会线索没有 CA。）

```
② 溯源
   a. 作者是我们已在盯的官方号（watchlist 的 official 行）  → 已经权威
   b. 帖子里有链接（展开 t.co）                            → 候选官网 / 文档
   c. 帖子里有 @账号                                       → 候选官方号
   d. 都没有，但有项目名 → **二次 X 搜索**（"<项目名>" + 帖里的区分词）
        搜的是帖子，账号从**结果的作者**里捞，最多读 3 个候选的资料页
   → 证据分级：
      A 互证（官网提到项目名/handle 且链回同一个账号）  → 当官方，trust = 官方
      B 同名 + 内容吻合（handle 近似 + 近期帖子与线索同题） → 进列表，但 trust = 社区，
        trust_basis 写「同名账号，未互证」；**不自动进 watchlist**
      C 只有同名 → 不进列表，记「未找到官方来源」
```

| 规则 | 说明 / 反例 |
| --- | --- |
| **A 级账号自动进 watchlist**（`official` 行），B 级不进。 | watchlist 的 `official` 行会让它**之后发的每一条帖子都自动变成官方**（`trust.py` 的规则），所以把一个可能是冒充的号加进去，等于把它以后所有内容都洗成官方。 |
| **默认每轮溯源上限 200 个项目**（按项目去重，4 个并发；可在设定页调整）。 | 一条线索走完解析、资料页、官网和文档约一分钟；不并发会把一轮拖成数小时。超上限的留在池子里，下一轮接着溯。 |
| **溯源失败要记账**：进未晋升池，理由写「还没溯源」或「未找到官方来源」。 | 这正是"为什么它没上列表"的答案，也是以后回头看"当初太早"的凭据。 |
| 读取器**复用 `search/`**（`identify.fetch_page` 含 Playwright 兜底、`base.links_in` / `host_of` / `handle_of`、`harvest.site_candidates`），不另写一份。 | 一个源一个适配器：读页面的那套已经写好了，第二份只会跟它漂移。 |
| 要重写的是**验证**：`identify` 的证明是"这一页提到了这个 CA"，这里没有 CA，等价物是"官网 ↔ 账号互证"。 | 按名字匹配天然会撞上冒充号（同名、加 `_official`），所以证据必须分级。 |

## 主题：一张卡 = 一个项目（2026-10-19, user）

**这是流水线的骨架，不是一次调参。** 之前的形状是「一条帖 → 一张卡」，于是同一个项目会出现
七张卡（CONSO 一次扫描就出了七张：声誉挖矿、白名单与 Genesis Mint、Genesis Mint 面向早期合格
参与者、可验证 Consumer Graph、用 AI 挖矿拿 ZAPs、生态内容活动、生态整合挖矿），而每张都是某条
社区帖的转述。用户的原话：**把每个卡片看作一个主题，它可以是多个 X 帖子、官网内容或者其他资料
汇总生成的**。

```
① 收集：多条 X 帖（官方号时间线 + 查询清单命中）
        ↓
② 归并成主题：按**项目**聚合（7 条 CONSO 帖 = 1 个主题）
        ↓
③ 溯源到官方：官网 / 文档 / 官方号（**社区帖是线索，不是材料**）
        ↓
④ 读官方内容（3–5 页）
        ↓
⑤ 出一张卡：这是什么 / 怎么做 / 有哪些限制
   材料 = 官方若干页 + 支撑它的那几条帖；页脚放官方 X / 官网 / 文档 / 原文与归档 / 删除
```

| 规则 | 说明 / 反例 |
| --- | --- |
| **一个项目一张卡**（user, 2026-10-19）：同一项目的多个活动合成一张，活动是卡里「现在能做什么」的几段。 | 每个活动一张卡 = 七张 CONSO；而读者要发现的是**项目**，活动会变、项目不变。 |
| **官方优先，社区帖只是线索与兜底**（user）：找到官方帖/官网就用官方材料写卡；只有社区帖时用社区帖写，`trust` 标为「社区」。 | 社区帖当材料写出来的卡，就是用户看到的「这么多社区贴很杂」——它们是**指向官方的线索**，不是权威内容。 |
| **讲不清就不出卡**：`summary` 必须回答「这是什么」（不是复述帖子）；活动还要有具体步骤与官方入口，项目只要有官方入口与一句「是什么」。含糊的进未晋升池，理由写「材料没说清」。 | 只要求「有步骤」，于是「前往置顶帖互动，对作者 @x 的置顶帖子进行互动，申请站点白名单」也算过关 —— 用户原话：不明所以，看的一头雾水。 |
| **生态是项目级事实**：从官方页读一次，该项目所有卡都带上。 | 现在是每条帖各读一次，于是同一个 Sui 项目有一堆「未判定」。 |
| 卡片页脚列出**官方 X / 官网 / 文档 / 原文**，再接**归档 / 删除**；来源清单存 `sources_json`（2026-10-25）。 | 只给原文链接，读者无法判断这条机制说明来自项目自己还是社区转述。 |
