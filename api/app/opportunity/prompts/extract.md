# 任务：把一条材料读成结构化条目（活动 / 项目）

上下文有：**材料正文**（一条 X 帖子，或一个网页正文 —— 平台列表页可能一次给出好几条）、
**来源**（账号或站点）、**来源 URL**、**材料时间**。

你的活不是评价，而是**把材料里真实存在的东西抄成结构**：有人能做什么、去哪做、什么时候、
要不要花钱、是什么东西。写出来的每一句都要能在材料里找到出处。

## 两类条目

- `activity` **可参与活动**：必须有 **steps**（参与步骤），每一步都能独立照做。
- `project` **新项目 / 新协议 / 新实验**：必须有 **summary**（一句"是什么"），**不要求 steps**。

一条材料可以产出 **0 条、1 条或多条** 条目：一条帖子通常一条，一个平台列表页可能好几条。
材料里既没有可参与的事、也没有可说的新东西，就返回空数组 —— **空数组是正确答案，不是失败**。

## 类目（必须从下面选一个）

- `activity`：打新 / 挖矿 / 节点 / 做任务 / 交互 / 空投 / 测试网 / Mint / 白名单 / 治理 / 其他
- `project`：新协议 / 新实验 / 新工具 / 新标准 / 基础设施 / 其他

三个容易混的类目：

- **节点**：跑验证者 / 节点 / sequencer / prover，或买节点、委托节点。看的是 VPS、在线率、
  质押；把流动性放进池子吃收益是 `挖矿`，不是 `节点`。
- **交互**：在已有协议上做链上动作（swap / bridge / LP / 质押 / 签到），换积分或潜在空投。
  优先级：**测试网 > 交互**（试用新网络算 `测试网`）；**做任务 > 交互**（有清单或社交步骤
  算 `做任务`）；两样都不是才算 `交互`。
- **治理**：治理投票、委托、ve 锁仓、gauge、提案。任务清单里要求去投票的，仍算 `做任务`。

## 铁律

- **先判断是不是加密内容**：材料里没有任何加密锚点（链、代币、钱包、合约、NFT、DeFi、
  质押、gas、主网 / 测试网、crypto / web3 等），返回 `{"entries": []}`。普通 SaaS、硬件、
  演出、订阅、书签工具、招聘、新闻都不是机会。
- **发射台新币快照不是机会**：单个代币的 `NEW LAUNCH`、市值 / 24h 成交量 / 持有人 /
  狙击者 / 捆绑者 / bonding curve 进度，除非帖子给出除“去交易”以外的参与动作（任务、空投、
  白名单、Mint、测试网、质押），否则返回空。
- **只写材料里真实出现的功能、活动、时间、链接。** 材料没提到的，一律留空字符串，不许推断，
  更不许用"通常""一般"这类常识补空。
- **一份材料可能是同一个项目的多条帖子**（每条前面有 `【@作者 时间】` 标记）：先回答「这是什么」，再把多条帖里说的「怎么做」**合并成一份步骤**，同一件事只写一次，不要为每条帖各写一条。
- **材料里若有「官方来源」一节，优先用它**：那是溯源读到的项目自己的官网与官方号。冲突时以官方来源为准，并在 `summary` 里只写官方说过的话。
- **材料没有「官方来源」时，只有社区帖**：`summary` 必须以「社区帖称，」开头；不得写“官方文档”“官方公告”
  这类把社区转述冒充官方原话的句子。只有 `官方来源` 一节或原帖明确给出的官网，才能填 `official_url`。
- **数字写出来**：名额、价格、比例、时间，材料写了就照抄。
- **截止时间只抽不猜**：材料没写 `deadline` 就留空。空着是"材料没说"，不是"没有截止"。
- **`barrier` 只能从这八档里选**（可多选，也可以一个都不选）：
  `无成本` / `需 gas` / `需资金` / `需质押` / `需白名单` / `需 KYC` / `需设备或挂机` / `需社交任务`。
  材料没说就不要选 —— **不要用"无成本"表示"没说"**。
- **`maturity` 只能从**：`实验性` / `测试网` / `主网`。材料没说就留空。
- **`ecosystem` 写项目所在公链的常用英文名，小写**（`ethereum` / `solana` / `base` / `bitcoin`…）。
  材料说它在哪条链上就写哪条；说了不止一条写 `多链`；一条都没说写 `未判定`。
  **不限于常见那几条**：写了别的公链（`aptos`、`avax`…）也照写，读取器会归一化。
- ~~旧规则~~ `ecosystem` 只能从这八档里选**：`bitcoin` / `ethereum` / `solana` / `base` / `bsc` / `sui` / `多链` / `未判定`。
  材料说它在哪条链上就写哪条；说了不止一条写 `多链`；一条都没说写 `未判定` ——
  `未判定` 是「材料没说」，`多链` 是「材料说它同时在好几条链上」，两者不是一回事。
- `organizer` 只填材料里出现的官方账号 handle（不带 @）；`official_url` 只填材料里出现的官网地址。
- `novelty` 只在发现轨道填写：新协议 `protocol`、新玩法 `gameplay`、新机制 `mechanism`、新标准 `standard`、新资产 `asset`、新链/生态 `chain`、新工具 `tooling`、新市场 `market`；没有就留空。
- 每一步的 `source_url` 填**材料的来源 URL**（你读的就是它），`source_at` 填材料时间。
- 步骤写不清就不要写这一步；一条 activity 一步都写不出，就不要产出这条 activity
  （降级成 project 也不行 —— 那是两回事）。
- 不要写"值得关注""潜力巨大"这类没有信息量的句子；`risk` 只写材料里点明的风险。

## 篇幅（硬上限）

- `title` ≤ 40 字；`summary` ≤ 200 字；`risk` ≤ 120 字。
- 每一步 `body` ≤ 200 字；**`steps` 最多 6 条**（更多的话合并同类项，不要截断成半句）。
- 写完自己数一遍：超了就删到上限以内。
