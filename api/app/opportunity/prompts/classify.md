# 任务：把一条材料判成「活动 / 项目 / 观点 / 资讯 / 其他」

材料是两种之一：**一条 X 帖子**，或**一个网页的正文**（可能是平台的活动列表页、交易所公告页、
生态目录页）。上下文里有：材料正文、来源（账号或站点）、来源 URL。

这一步只回答一件事：**这条材料里有没有"有人能做的一件具体的事"，或者"出现了一个值得看的新东西"。**
不要抽取步骤、不要写摘要 —— 那是下一步的活。

## 三档

- `activity` **可参与活动**：材料里说了"去哪、做什么"，人照着能做。打新、挖矿、做任务、空投领取、
  测试网 / 公测、Mint、白名单都算。
- `project` **新项目 / 新协议 / 新实验**：出现了一个东西（协议、工具、标准、实验），**不要求有参与动作**。
  判据是"说得清它是什么"，而不是"能不能参与"。
- `opinion` / `news` / `other`：观点、资讯、行情、喊单、与上面都无关的。

## 类目（必须从下面选一个，不许自己造）

- `activity`：打新 / 挖矿 / 做任务 / 空投 / 测试网 / Mint / 白名单 / 其他
- `project`：新协议 / 新实验 / 新工具 / 新标准 / 基础设施 / 其他
- 判 `opinion` / `news` / `other` 时，`category` 留空字符串。

## 铁律

- **只判材料里真实写着的东西。** 读不懂、看不懂、只有一句口号，一律 `other`，不要猜。
- 一条材料同时在讲观点和活动：**判 activity**（能做的事优先）。
- 一条材料同时讲一个项目和它的活动：**判 activity**（活动是更强的信号，步骤那一步会把项目信息一起带出来）。
- 一条平台列表页上列着很多活动：判 `activity`，类目取其中最主要的那一类。
- 中文材料用中文类目，英文材料也用上面这套中文类目（**不要自己翻译成新词**）。
- 只输出 JSON，不要多余文字、不要 markdown 代码块以外的解释。
- **`name` 写项目 / 团队的名字**（拥有那个官方账号的名字，通常与它的 handle 相近），
  **不是产品功能名**：CONSO 发的帖子写 `CONSO`，不要写 `Consumer Graph`。
  它是溯源的搜索词与主题的归并键，写成产品名会让两者都对不上。
- ~~旧规则~~ **`name` 写项目自己的名字**（材料里的写法，中英文照抄，不翻译、不补全）：它用来把这条
  线索溯源到项目自己的官方号与官网，所以**只写材料里真的出现的名字**。材料没有名字
  （一句感慨、一个问候、一个来路不明的 `$cashtag`）就写空字符串 —— 空着会被当作
  「没有名字」，而编一个名字会让溯源去搜一个不存在的东西。

## 输出（严格 JSON）

```json
{
  "kind": "activity",
  "category": "测试网",
  "name": "Spout Finance",
  "why": "官方宣布测试网已对所有人开放，并给出了入口与参与方式，属于可参与的活动"
}
```
