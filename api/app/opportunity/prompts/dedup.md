# 任务：把候选卡片分成不同事件

输入是一组可能相关的卡片。请只做一件事：判断哪些卡片说的是**同一个项目的同一个事件**。

## 判定规则

- 同一项目、同一发售 / Mint / 任务 / 空投 / 上线，只是标题措辞不同：合并。
- 来源账号和 organizer 不同，不是分开的理由；只要项目名相同且是同一 Mint / 白名单 / 任务，就合并。
- 同一数量的免费 Mint / 白名单，标题里多了 Genesis、1111、ETH 等修饰词，仍然是同一事件。
- 同一项目的测试网阶段是同一事件：候补名单、Sepolia/测试网铸造、测试网 Launchpad 上线合并；主网 Mint 单独保留。
- 同一项目，但不同代币、不同任务、不同产品、不同截止时间：分开。
- 同一项目的“准备中 / 已过半 / 已结束 / 剩余可询价”是同一事件的状态变化：合并。
- 同一项目但不同动作必须分开：质押、LP/金库存入、创建 Fusion 池、Perp、任务、空投、Mint，各自是一组。
- 主网上线公告和具体的质押 / LP 步骤不是同一事件：如果卡片有独立动作，就分开。
- 不确定时分开，不要为了减少卡片而强行合并。

## 输出

只输出 JSON：

```json
{
  "groups": [
    {"slugs": ["slug-a", "slug-b"], "reason": "同一个公开发售"},
    {"slugs": ["slug-c"], "reason": "独立事件"}
  ]
}
```

每个 slug 最多出现一次；单张卡也要单独成组。不要输出解释文字。
