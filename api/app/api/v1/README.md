# HTTP 层与页面文案

`api/v1/` 是全仓唯一 HTTP 层：`chains` / `runs` / `lexicon` / `settings` / `favorites` / `lookup` / `system` / `health`。页面上的解释性文案只在 `forms.py`；一轮的「口径」三行在 `core/caliber.py`（落库与页面要输出同一句）。系统设置页读写 `config/system.yaml`。

## 设定页

设定页是 yaml 的前端：一次保存写一个 dotted-path 的 patch 落到存档版本，出厂默认来自模板；页面只放有代码读的旋钮。

| 规则 | 说明 / 反例 |
| --- | --- |
| 保存走 `settings_versions`（不可变，之后以表为准），出厂默认在 `config/chains/*.example.yaml`。**链与链不共享设定，同一条链的多套设定之间也不共享**；落到两层以上的组里要**深合并**。 | 浅合并的 `{**a, **b}` 会把先改的那个整组覆盖。被拒绝的保存须写成操作者可直接照做的一句话（中文、带当前值、把 key 译成页面上的行名）—— 前端不翻译，只把 `detail` 输出。 |
| 一条链一个 yaml：文件里 `configs` 是这条链的一套套设定，链自己的事实（`explorer` / `rpc`）写在文件顶层、不进 `configs`。内部名字是 `arc:wide` 这种复合 id，落库是 `chain_id` ＋ `config_id` 两列。`default` 带 `locked`，任何链都保留，不可删除。**每条链同一时刻只跑一套**。 | 跟仓库的只有 `<id>.example.yaml` 模板，运行时那份 `<id>.yaml` 首次读时从它播种、不入库 —— 页面写入都落在后者，因此切换配置不会污染 git 工作区。**新增一条链就是新增一个文件**：`_chains_signature` 按目录里每个 yaml 的名字 / 大小 / 时间戳做缓存键，新增的链文件立即生效，无需重启。 |
| 隔离的边界：`settings_versions` / `runs` / `reports` / `lexicon` / `previous_picks` 都按设定分开；**不隔离**的是 `tokens` 与 `peak_market_cap_usd` —— 那是链级事实，与哪套在看它无关。 | 几套设定并排跑只会争用同一批源与限流，使第一套更慢。 |
| 名字与 id 分开：`config_id` 随机生成、**永不改、永不复用、不上页面**；页面上写的一律是 `label`（链内唯一）。新建的一律 `enabled: false`；`PUT /settings` 除存 patch 还调 `set_active_config()`（按钮就叫**保存并生效**）。**每条链最多一个 `enabled: true`**，多过一个说明数据异常：只保留一个并把说明写进 `ChainOut.warning`，链仍可正常读取。 | 反例：把 `config_id` 当 label 用，改名就要动五个主键和每条 run 的 key。直接报错会让整条链无法打开，而只有操作者能决定保留哪一个。 |
| 拒绝分三个码（400 名字问题 / 404 没有这套 / 409 现在不能动）；删除前须**原样输入一次** label，并连带清空这套的全部痕迹（`runs` / `reports` / `snapshots` / `lexicon` / `settings_versions` 与 `data/raw/<run_id>/`）；**`tokens` 与 `llm_calls` 不动**。 | 点击即可通过的「二次确认」不算确认。文件是**往返改写**不是重写（`ruamel.yaml` 保注释、保引号、保 CRLF），改完 `arc.yaml` 往返应当逐字节相同。 |
| 解释折进「说明」icon，判据是「这句是这一轮的**读数**，还是关于字段本身的规定」：读数留屏幕，规定进 icon；**文案仍只在 `forms.py`**。 | 标题下面多一行解释，整屏都是灰字，用户找不到真正的读数。 |
| `市值` 与 `持有人` 都是**区间**（上限与下限共用同一条规则，所以淘汰计数、漏斗行都不用跟着改）；设定页只多一条 —— **空格子必须能存回去**（空 → `None`，数字 → `int`）。链下五项各 0–5、按 `offchain_factor_weights` 合成，与链上那一半**同形**。 | 把上限写成 `0` 就是「一个都不留」；缺键当 0 权重会把没有这个键的老快照的币全数淘汰；改一个权重不把合计调回 100 就是 422（见 `CLAUDE.md` · 边界与待决）。 |
| 设定页只放**有代码读的**旋钮：「提醒」那一组四个开关没有任何代码读取，勾选与否一轮结果完全相同，已整组删除（三个 yaml 模板里的 `alerts:` 块一并删）。数据仍然保留：改名次数由 GMGN 输出在事实表，官网 / X / TG 链接照在页脚。 | 一个静默的空开关比缺少一个旋钮更糟：会让用户误认为它已经生效。 |
| **组数 ＝ 轨道数**，轨道按**块名**认领：`block.columns` 只管断点以下的 auto-fit；断点以上（`app.css` 的 `min-width:1668px` media query）由 `data-blk` 逐个硬写轨道。 | 轨道多于组时多出来的那条仍会占位，页面不报错、几何也看不出错；块改名留下的**死选择器**被当作「尚未编写的模板」指向真实块，那块会压成三分之一宽。 |

## 系统设置（本机接线）

左栏最下面那一行。它管的是**这台机器的接线**，不是任何一轮的口径 —— 不属于任何链，也不是设定页那种按链的设定。工作全在 `api/app/system_settings.py` ＋ `api/app/api/v1/system.py` ＋ `web/src/features/system/`。它也是全站唯一画**可编辑字符串行**（`Widget` 的 `text` / `password`）与唯一带**探测按钮**的地方（端点：获取模型 / 测试连接；X 会话：测试连接）。

| 规则 | 说明 / 反例 |
| --- | --- |
| **一个文件两个面**：`config/system.yaml` 由 loader 灌进环境变量，页面是它前面的一张表单，两边都走 `config.SYSTEM_KEYS` 那张键表 —— 页面**提不出无人读取的旋钮**。键名去前缀、按块嵌套（`llm.base_url` / `x.auth_token` / `log_level`）。 | 页面另行复制一份键名清单，改一处漏一处，就是「设了没反应」。 |
| **真实环境变量永远优先**：操作系统给了值的那一行画成只读、dim 写「环境变量」；**来自文件的行不写 dim**。 | 把文件写下去而进程仍在读另一个值，就是一次操作者看不出效果的保存；反过来，把正常情况也标出来，真正异常的那几行会被淹没。 |
| **空 ＝ 没配，不是空串**：`null` / 缺键 / 空框都不写进环境变量。**唯一例外是密钥**：密文框空着 ＝ 保留已存值。 | 写 `""` 会让 `float(os.environ.get(..., "180"))` 直接报错；密文框按「清空」处理，一次误删就得换 key。 |
| **密钥页面只给两端，不给值**：写成 `已配置 · sk-liv…6789`（首 6 尾 4，短于 12 位只给尾），没配的写「未配置」；日志那边只输出 sha256 前 8 位。 | 值进了 HTTP 响应，就等于进了浏览器缓存、截图和每一次复制；两端已经够回答「用的是否是已记录的那把」。 |
| **写回是行级往返**：`ruamel.yaml` ＋ 临时文件 ＋ `os.replace`，没改的行逐字节相同。非法值（枚举写错 / 数字不是数字 / 不是 JSON / `NaN`）一律 422 且**文件不动**。**保存即生效**：写完重读环境变量并重新挂载日志（幂等），日志等级**立即**换档；LLM 与 X 会话是**下次调用**换。 | 整份重写会破坏注释与排版；先写坏再报错，会把文件留在未经校验的状态。 |
| **探测走草稿，不是文件**：`POST /system/models` 与 `POST /system/test` 都带 draft，用 `effective()` 把草稿盖在文件上、走保存那套同款校验 —— 存不进去的值在这里也是 422，而且**什么都没写**。**它不是一轮**：`api_keys` 里**每一把各打一次**、不重试、60s 超时、**不写 `llm_calls`、不把任何一把 key 置入冷却**；网关的拒绝是**答案不是异常**，原文显示在按钮旁边。 | 若必须先保存才能测试，操作者只能先把一个错误的端点写进文件才能发现它错；一次误点按钮就会把真实 key 置入 600 秒冷却，比不点这个按钮更糟。备用 key 一轮只在主 key 被拒的那天才第一次用，那时才会发现它同样不可用，代价是一整轮。 |
| **测的是「能不能写」，不是「通不通」**：`/models` 只证明端点可达，所以 `test` 每把各打一次**真实的最小调用**（`max_tokens=256`，按配置发 `reasoning_effort`），一并回报 `finish_reason` 与字数。 | 只看连通性，会把一个「200 ＋ 空正文」的端点判成健康，那正是链下调研曾遇到的情况（见 `report/README.md` · 链下调研）。 |
| **候选只写入输入框**：端点预设（`forms.SYSTEM_ENDPOINTS`）与端点返回的模型列表都是 `Pick`，点击后写入旁边的输入框，**输入框仍保持可编辑**。按钮与结果行由后端的 `ActionOut` 给，`id` 是这一页唯一认识的词。 | 做成纯下拉，则自建 vLLM、或端点未列出的模型都无法使用。 |
| **X 会话的「测试连接」问的是「这串 cookie 还是登录态吗」**：`POST /system/x` → `XEngine.probe()` 跑一次 `twitter whoami --json`（`PROBE_TIMEOUT` 30s，不是一轮的 120s）、不搜关键词、不记账、不碰冷却；拒绝的原文回页面；缺凭据 / 未安装客户端 / 超时各自成句，而不是返回 500。 | X 没有 `/models` 那种免费探针；验证会话须发起一次真实搜索，误点一次即消耗一轮所需的额度。 |

## 新机会

左栏那一行。它管的是**外部世界**：X 上出现的活动与新项目（2026-10-18 起 X 单源：`official` 账号时间线 + `query` 查询，后者按时间切片）。不属于任何链，也不属于任何一套设定 —— 一个活动不会因为换了一套设定就变成两条（见 `api/app/opportunity/README.md`）。

| 规则 | 说明 / 反例 |
| --- | --- |
| **一次读给全页**：`GET /opportunity` 返回条目（含步骤）、计数、最近一次扫描与页面文案。 | 拆成四五个请求，页面就要自己拼一个「这一屏」出来，而拼装是判定 —— 分数与文案都只在后端。 |
| 扫描的计数里多三项：`traced`（A/B/C 各几条）、`trace_skipped`（超上限或被去重）、`added`（A 级自动进 watchlist 的账号）。 | 溯源是这一轮最贵的一步，"这次溯了几条、跳了几条"必须看得见，否则积压会变成沉默。 |
| 四条新端点：`GET/PUT /opportunity/settings`（九个旋钮，`fields` + 分块 `blocks` + `dirty_hint` 都由后端给；保存只写 override）、`GET /opportunity/scans`（历史轮次，归档 tab 与时间条读它）、`GET /opportunity/queues`（未分组 / 未抽取 / 溯源失败）、`PATCH /opportunity/items/{slug}`（归档 / 删除 / 恢复）。 | 设定是旋钮不是事实，所以存 `config/` 不进数据库；排队视图回答"我见过的东西去哪了"，队列不可见就等于丢失。 |
| 阶段行带**阶段内进度**（`done` / `total`）：一个六分钟的 collect 只报「running」，页面就等于卡住。 | 只报状态的进度条在长阶段上和死机没有区别。 |
| 扫描是**可轮询的 job**，不是一轮：`POST /opportunity/scan` 返回 202 与扫描行，`GET /opportunity/scans/{id}` 轮询它，六个阶段与计数都写在那一行上（计数里的 `queries` 是 X **调用**次数，因为一条查询会切成好几片）。 | 扫描不属于任何链，写进 `runs` 就会出现在那条链的轮次列表里，读起来像那条链又跑了一轮（与 CA 搜索同一条理由）。 |
| **可以中止**：`POST /opportunity/scans/{id}/cancel`，幂等、对已结束的扫描返回 `cancelled: false` 而不是 404；扫描停在下一次 X 调用上。 | 扫描通常卡在限流上，"跑完这一段再停"等于让读者再等四十秒。 |
| 一次只跑一个扫描：已在跑时 `POST` 返回 **409**，不是排队。 | 两次扫描读同一批时间线，X 的节流会把它们串起来，第二次只是晚到且花两倍的钱。 |
| 未晋升的条目**跟着晋升的一起返回**，靠 `status` 区分；`reason` 已经是读者的句子。 | 只返回成功的那些，「为什么这个没上列表」就没人能回答。 |
| 筛选面板与排序键也在这**一次读取里**（`filters` / `sorts`），由后端建：**两组（生态第一 + 状态）**、选项名与排序键都在 `forms.py`，**只有真有两个取值的分组才发**。 | 前端硬编码类目表，后端加一个类目就要改两处；把只有一种取值的分组发出去，页面上就是一个只能筛空的开关。 |
| 过滤与排序在**前端**做，这一次读取本来就是「一次给全页」；热度**不是**排序键（它是来源帖自己的读数），排序只有发现时间与截止时间。 | 每改一次筛选打一次后端，等于给已经拿到手的列表加一次往返；拿热度排序，等于让「谁被看见」取决于我们读了哪些号。 |
| 解释性文案（空态、trust 的说法、未晋升池与 watchlist 的说明）由 `forms.opportunity_form()` 提供；按钮名留在页面上，与 CA 搜索页一致。**页头没有说明段**：2026-10-18 起去掉（user），热度口径挂在徽章的 tooltip 上。 | 前端另行写一份口径，改一处漏一处，就是同一页上有两种说法。 |
| watchlist 与条目这一版**只读**：没有增删端点，页面上也没有对应按钮。 | 「一个静默的空开关比缺少一个旋钮更糟」：按钮按不动比没有按钮更坏。 |

## 为什么这么定

每一条都是由一个具体的错误纠正出来的；现行口径见右列。

| 曾经的错 | 现在写在哪 |
| --- | --- |
| 设定 patch 在两层嵌套组上做浅合并 → 同一次保存改两个权重只留下最后一个 | 本文件 · 设定页 |
| 设定页曾有一组四个「提醒」开关，没有任何代码读取它；勾选与否，一轮的结果完全相同 | 本文件 · 设定页 |
