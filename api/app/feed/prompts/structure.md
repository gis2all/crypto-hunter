# 任务：把一条行业资料抽成结构，不写读者看的字

上下文是**一条**刚抓到的记录，可能来自英文媒体、中文媒体、交易所公告、官方博客或 X。
材料分两块（推文引用了别家时，正文后还会多一段「引用推文」）：

1. **来源块**：名称、类型、分级、是不是一手来源 —— 只用来判断这条话的分量，不是让你抄；
2. **发布时间**；
3. **作者**：源自己署的名，可能没有；
4. **原文标题**：源自己写的，可能不是中文；
5. **原文正文**：源自己给的正文，**可能为空，或只有一句摘要**；
6. **候选实体**：这条材料里认得出的实体 id，可能是「无」；
7. **原文链接**：这条材料的地址，只用来核对。

只做结构化抽取：**不写标题和摘要，不打分，不判断是否精选**。

## 一、类别 `category`（{{categoryCount}}选一）

{{categoryGuide}}

## 二、标签 `tags`

输出 1–6 个字符串。第一个必须从以下**分类标签**中选一个：{{categoryTags}}。
其后可选 0–5 个适用标签，只能来自以下两个白名单：

- 主题：{{topicTags}}
- 实体：{{entityTags}}

没有适用的主题或实体时，只返回分类标签，不要凑标签。

## 三、主体 `subjects`

资料**实际讨论**的主体（不是顺带提及），用这些 id：{{entities}}。
没有就给空数组。**只能原样抄这些 id**，候选里没有的一律不算。

## 四、事实 `fact`

这条资料报道的**核心事实**，用于把同一件事的多篇报道归到一起：

| 字段 | 写什么 | 上限 |
| --- | --- | --- |
| `subject` | 谁做的 | 40 字 |
| `action` | 做了什么 | 40 字 |
| `object` | 对什么做的 | 40 字 |

观点、评论与盘点类资料可以给 `null`。材料没说清谁做的、或没说清做了什么，那一格就留空串 ——
拿标题里的词硬凑一个骨架，比空着坏得多：编出来的骨架会让两件不相干的事看起来像同一件。

## 铁律

- **只写材料里有的事。** 正文里没有的数字、金额、日期、人名、机构名一个都不许出现。
- 类别与标签是**判断**不是抄写：拿不准就选最上面那个兜底的类别，标签宁少不多。
- 不许把材料里的字段名（「来源」「作者」「原文标题」「原文正文」「发布时间」「原文链接」）写进答案。

## 输出

只输出一个 JSON 对象，不要任何解释文字：

{{> safety}}

{{> rules-anti-hallucination}}

{{> rules-domain}}

```json
{"category": "security", "tags": ["安全", "跨链", "Ethereum"],
 "subjects": ["ethereum"], "fact": {"subject": "Nova Bridge", "action": "drained", "object": "1200 万美元"}}
```
