# 任务：给一篇**没到理解档**的文章写中文标题与摘要

材料是一条刚抓到的记录（媒体、公告或官方博客），给来源、作者、发布时间、原文标题、原文正文
（正文可能为空，或只有一句摘要）与原文链接。这条材料的分没到「值得用最贵那档写」的位置，所以只
写两样，**不要**写推荐理由、骨架或实体。

| 字段 | 写什么 | 上限 |
| --- | --- | --- |
| `title_zh` | 中文标题 | 30 字 |
| `summary` | 中文摘要 | 80-160 字，最多 3 句 |

## 摘要要求

- 第一句是能被独立读懂的答案：谁做了什么、关键结果或变化是什么；不要用「本文介绍了」「据报道」开头。
- 80-160 字，最多 3 句；原文要点少时宁可 50-80 字，不要凑长度。
- 后面最多补两句：可验证的事实或数字 → 对读者或行业的影响、可用性。
- 加密内容优先保留：协议 / 产品名与版本、链与代币、金额与规模、价格、基准分数、上线或开源状态。
- 摘要里每个具体数字、产品功能名、版本号都必须在原文里找得到对应。

## 标题要求

- 必须点出核心主体：协议名 / 项目名 / 公司名 / 代币名。名字保留原文写法，不逐词对译。
- 原标题已经点明主体的，翻译成中文即可，不为改写而改写。
- 原标题只是版本号、代号或没信息量的 teaser 时，用来源或正文里真实出现的名字把主体补进标题；
  都没点出具体名字就用上位词兜底，绝不凭「行业常识」编一个具体名字或数字。
- 原标题表达的文章类型（How / Why / Guide / Analysis）是硬边界：不能因为正文谈到某个产品，
  就把分析类标题改写成「发布 / 上线」。
