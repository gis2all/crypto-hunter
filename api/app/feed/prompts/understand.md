# 任务：把一条行业新闻写成中文的标题、摘要、推荐理由与标签

上下文是**一条**刚抓到的记录，可能来自英文媒体、中文媒体、交易所公告、官方博客或 X。
材料给这几样（推文引用了别家时，正文前还会多一段「引用推文」）：

1. **来源**：谁说的，括注类型与分级；
2. **作者**：源自己署的名，可能没有；
3. **发布时间**；
4. **媒体**：这条带了几张图 —— 图的内容不给你，别猜；
5. **原文链接**：这条材料的地址，只用来核对；
6. **原文标题**：源自己写的，可能不是中文；
7. **原文正文**：源自己给的正文，**可能为空，或只有一句摘要**；
8. **材料质量**：正文是抓来的、源自带的、还是只有标题 —— 材料越薄，能说的越少；
9. **候选实体**：这条材料里认得出的实体 id，可能是「无」。

一次写完四样，全部用中文。类别、主体与事实骨架由「结构抽取」那一档负责，不在这里写：

| 字段 | 写什么 | 上限 |
| --- | --- | --- |
| `title_zh` | 这条的中文标题 | 30 字 |
| `summary` | 摘要：发生了什么、结果是什么 | 80–160 字 |
| `reason` | 这件事为什么值得一个行业观察者花时间看 | 60 字 |
| `tags` | 1–6 个标签，第一个必须是分类标签 | 6 个 |

## 标签 `tags`

输出 1–6 个字符串。第一个必须从以下**分类标签**中选一个，且要与这件事的实际类别一致：
{{categoryTags}}。

其后可选 0–5 个适用标签，只能来自以下两个白名单：

- 主题：{{topicTags}}
- 实体：{{entityTags}}

没有适用的主题或实体时，只返回分类标签，不要凑标签。

## 铁律

- **只写材料里有的事。** 正文里没有的数字、金额、日期、人名、机构名、合作方，一个都不许出现。
- `title_zh` 用中文新闻的写法，不逐词对译；代币名 / 协议名 / 公司名 / 人名**保留原文写法**。
- 材料里有「引用推文」时，把**它承载上下文的关键点整合进 `summary`**：只整合关键点，不逐句复述、
  不照搬全文。它同样是材料，所以「材料里没有的事不许写」照旧。
- 原文本来就是中文的，照它的意思写，不要改成标题党。
- `summary` 说的是**这条材料**说的，不是你对这个赛道的看法。材料没有结论就写清「目前只是…」。
- `summary` 最多三句；原文要点少时宁可 50–80 字，不要凑长度。列表与详情页印的是同一串字。
- `reason` 不许是套话（「值得关注」「影响深远」「意义重大」都不算）。说不出具体理由，就写这条
  材料本身说明了什么。
- 无 emoji，无反问句，不留裸 URL，不用「震惊」「重磅」「炸裂」这类词。
- **不许把材料里的字段名写进答案**：「来源」「作者」「原文标题」「原文正文」「发布时间」「材料质量」是你读的路标，
  不是文章的一部分。答案里出现这些字样，这一条就作废。
- 来源是当事方自己（公告 / 官方博客 / 官方账号）时，`reason` 要让人看出这是**一手**说的。
- 标签是**判断**不是抄写：白名单外的一律不算，宁少不多；第一个是分类标签，其余才是主题与实体，
  没有就只写分类标签。

## 材料不足时

正文为空、或短于 120 字（只有一句摘要）时：

- `summary` 只写标题能支撑的那一句，**不许补**任何标题里没有的事实；
- `reason` 写「目前只有标题、还没有可核实的正文」，或者写标题里那个动作本身意味着什么；
- `summary` 就是把标题的意思用中文说一遍，**不许带「原文标题：」这类前缀**。
- 宁可短，也不要把不知道的写成知道的。

## 输出

只输出一个 JSON 对象，不要任何解释文字：

{{> safety}}

{{> rules-anti-hallucination}}

{{> rules-self-contained-title}}

{{> rules-answer-first-summary}}

{{> rules-domain}}

```json
{"title_zh": "...", "summary": "...", "reason": "...", "tags": ["安全", "跨链", "Ethereum"]}
```
