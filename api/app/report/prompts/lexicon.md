# 任务：为「未建档」的标的写第一份词条

上下文里是标的的**完整事实表**（`【标的】【行情】【价格走势】【筹码】【持有人前 5】【供应与烧毁】
【税】【貔貅】【池】【池明细】【安全】【部署者】【身份】【社媒与官网】【项目自述】【交易页】`）。
它们**没有**词条库条目，而本链的口径是「未入库标的：待建档，本轮不参与排名」—— 所以不写就没有
产品分，没有产品分就进不了排名。

## 铁律

- **这一遍只有事实表，没有页面正文。** 表里的链接（官网 / X / GitHub / 交易页）是入口，不是你
  读过的内容：不许写「官网写明…」「X 称…」这类并没有读到的句子。流程后面有一步专门读页面并重写
  词条，这一遍只写表里能确证的东西，确证不了就写「—」。写「没有公开信息」之前，先确认表里确实
  没有链接。
- **每个数字都带出处。** 市值、流动性、持有人、税、烧毁、池占比都写数值本身（例：`市值 $147.6K`、
  `烧毁 4.12%`、`主池占 97%`），不要用「较高」「大幅」「显著」这类没有刻度的词代替。
- 只写你实际核过的事实。不编造 URL、产品功能、合作方、粉丝数。
- **链接写成「说明 + 可点击词」**：`官网 <a href="https://solonpad.fun">solonpad.fun</a>`、
  `X <a href="https://x.com/Solonlabs1">Solonlabs1</a>`。不要只贴裸 URL，也不要贴了链接却不说明。
- **安全只照抄，不自己推断。** 涉及源码 / 权限 / LP 的句子，必须一字不改地引用事实表 `【安全】`
  行的原文（例：`源码 已验证 ｜ 危险权限 无危险权限 ｜ LP 已锁`）。不要自己看合约下结论，也不要
  把「未判定」写成「没有风险」——写岔了，就是卡片上的安全块被自己的结论否定。
- 无 emoji，禁反问句。
- 每个标的都要写全 9 个字段，不要漏。

## 不许重复，不许编造

- `concl` 与 `narr_text` **严禁重复**：同一个事实只写一次。叙事由 `concl` 第一段承担；
  `narr_text` 只写 `concl` 没覆盖的内容（定位、机制、竞争位），确实没有新内容时直接留空字符串 `""`。
- 提到推文 / 公告 / 帖子等外部信息，必须附上**你实际读到的**原文 URL；查不到就不写链接，
  禁止编造 URL。
- 一律不留裸 @handle：账号写成完整链接（X 写 `https://x.com/handle`，TG 写 `https://t.me/名字`）。

## 叙事与机制怎么写

- `narr_text`：只补 `concl` 没覆盖的东西（定位、机制、与官方主线的接点、竞争位）。叙事由 `concl` 第一段承担，所以这里通常留空 `""`。
- `mech_text`：**是否有回购 / 燃烧 / 分红机制**（事实表或公告里写明的那部分，谁触发、什么比例），
  以及 **dev 的持仓与行为**（dev 是否仍在买入 / 卖出 / 未动）；数据里说不了的写「—」。

## social 字段格式

`「handle · 粉丝数 · 备注」`，不带 @，并且 **X / TG / 官网都写成可点击的链接**（见上面的链接写法）：

`X <a href="https://x.com/Solonlabs1">Solonlabs1</a> · 916 粉丝 ｜ 官网 <a href="https://solonpad.fun">solonpad.fun</a>`

没有的项省略，全无则留空字符串。服务端会把这一轮真实解析到的链接补在社媒块末尾，所以这里只写你
读到的那部分就够了。

## 评分

- `narrative` 看赛道叙事贴合度：Arc 上正在发生的事（RWA、稳定币、Agent、隐私等）与这个标的的关系有多直接。
- `product` 看产品完成度：有能打开的官网 / 文档 / 仓库，链上也有真实使用痕迹，才给 4 以上；
  只有一条推文和一张图，给 2 上下；一个页面都读不到，给 1 上下，并在文字里说明读不到。

## 篇幅（目标 700 字以上；下面是每字段上限，写完自己数一遍）

- `concl`：**200–500 字**，只做两件事。
  ① **主体：讲清这个项目是什么。** 以项目为主语连续叙述 —— 它是什么（链 + 赛道 + 定位）、在做什么
  （产品、机制、钱从哪来）、凭什么（独有之处、与 Arc 主线的接点）。**第一句必须是身份句**，让没听过的
  人一眼知道它是干什么的。**不要**用「官网写明…」「X 称…」「GitHub 自述…」当句子骨架（那是考据记录，
  不是叙事），只有引用公告原文时才出现一次。不要用「该项目」「致力于」这类空壳句式。
  ② **结尾：一条最关键的风险**（事实性，例：LP 未判定、权限未验证、陷阱占比偏高）。
  读起来要像写给同事的内部结论，不是写给项目的广告。
- **不写观点句**：「本批唯一…」「第一梯队」「值得关注」这类评价一律不写，判断留给读者。
- **不写数字段**：市值 / 流动性 / 持有人 / 量能 / 筹码不必罗列（表格与卡片上都有），数字只在叙述需要
  它的时候出现（例：「平台收 1% 兑换费」）。
- `narr_text`：≤150 字，可以为空。
- `prod_text`：≤200 字。写「现在能做什么、做到什么程度」，并且只能写事实表能确证的部分
  （项目自述、链接是否存在、池 / 税 / 持仓），句末标明依据。表里没有页面正文，所以不许凭「有官网
  链接」推断出功能；没有依据就写「未调研（无页面正文）」。
- `mech_text`：≤200 字。同样只写事实表能确证的机制与 dev 行为，读不到的写「—」。
- `pros`：≤100 字，讲量能与筹码结构、机制是否兑现、与主线的贴合。
- `cons`：≤100 字，讲流动性深度、筹码集中度、机制未兑现、赛道竞争。
- **上限是硬要求**：每个字段写完后自己数一遍字数，超了就删到上限以内 —— 系统不会替你精简，
  它只会把超长的原样存下来。
- 全部是事实，不写「值得关注」「潜力巨大」这类没有信息量的句子。
