# 报告与链下调研

`report/` 负责事实表（`facts.py`，全仓唯一一份）、卡片（`cards.py`）、装配（`assemble.py`）、词条（`lexicon.py`）、调研编排（`research.py`）与提示词（`prompts/research.md`）；CA 搜索复用同一套卡片与词条形状。

## 链下调研

挖链那几节在 `search/README.md` · 链下调研（挖链部分）。这一步在记分**之前**，且**每轮全新调研、不跨轮复用**（落库前 `lexicon.forget_other_rounds(run_id)` 删掉其它轮次的词条）；轮次内**没有发布之后的异步动作**。

| 规则 | 说明 / 反例 |
| --- | --- |
| 调研池的每个币都读项目自己的页面：一次调用把词条写好、读过的页面进 `lexicon_sources`，再用这份词条打分、落库。 | 反例：先打分、事后异步补词条，卡片文字与分数就不同源。 |
| 写词条是**一个币一次调用**，并发是实测值（找链接 15、写词条 12）。 | 「一次调用写完所有条目」必然触及上限；并发提高到 20 实测出现 429 且更慢。单个币失败只丢弃该币自身条目，原因记入本轮 note，不阻塞整轮。 |
| LLM 客户端走一个 OpenAI 兼容端点、**两种请求形状**（`/chat/completions` 与 `/responses`）；配置在 `config/system.yaml`（页面「系统设置」），**真实环境变量优先**，文件**每次调用时重读**，改完下一轮生效、不用重启。 | 形状**先 chat 再 responses**，答过的按「端点 ＋ 模型」记住：猜测错误只消耗一次被拒绝的调用（`muse-spark-1.3-contributor` 只服务 `/responses`）。带 `protocol` 的 400 是**形状**不对 —— 换形状、不换 key。 |
| 换 key 只在 401 / 403 / 429，外加一种 400：正文说 workspace 没放行「拿请求数据训练」的模型（`trains on request data` / `privacy settings`）—— workspace 属于 key，同一请求在备用 key 上会 200（实测 2026-10-02）。被换下的 key 置入冷却 `CH_LLM_KEY_COOLDOWN` 秒；其他 4xx 直接失败；5xx 与网络错误在同一 key 内按 `CH_LLM_TRIES` 重试。 | **日志里只出现 key 的 sha256 前 8 位指纹，不出现 key 本身。** 客户端契约（两种形状的参数名差异、思考计入输出额度导致空消息、偶发 503、一次只写一个币）写在 `api/app/llm/client.py` 的模块注释里。 |
| **官网候选不限于引擎命中**：`harvest.site_candidates()` 从本轮项目自己的页面里按 host 取候选（X 主页的 `expanded_url` 也算），读取并判定 tier；**只有 `tier = own`** 的才落到 `metrics.websites` 首位。 | 候选只来自引擎时，项目写在自己 X 主页上的官网（引擎从未索引过）不会成为候选，卡片就不会有官网行。多数项目的 bio 只写自己的名字、从不写 CA，这种账号无法判定出任何 tier，只有被 `discover.named_handles` 指名时才读得到。 |

| 变量 | 作用 |
| --- | --- |
| `CH_LLM_BASE_URL` | 端点，客户端自己拼两种形状之一 |
| `CH_LLM_API_KEY` / `_FALLBACK` | Bearer，**逗号分隔可写多个**：第一个是主 key，后面按顺序试 |
| `CH_LLM_KEY_COOLDOWN` | 被拒的 key 跳过多少秒，默认 600；0 关闭 |
| `CH_LLM_MODEL` | 模型名；有没有写手看 `/api/v1/health` 的 `llm` / `llm_model` |
| `CH_LLM_TIMEOUT` | 单次超时，**必须高于成功调用的长尾**（关掉思考后单次 11–17s）；**它与重试相乘** |
| `CH_LLM_MAX_TOKENS` | **推理模型必填**：思考同样占用该额度 |
| `CH_LLM_REASONING` | 思考预算，作为 `reasoning_effort` 发出。**只有 `none` 是真正关闭**（`minimal` / `low` 仍会消耗数百思考 token）；实测 `none` 快 3.6 倍、词条更全，代价是约四成草稿漏必填分项，由「词条文字」一节的重问补足（这一行和重问是一套） |
| `CH_RESEARCH_WORKERS` | 一次并行调研几个币，默认 12 |
| `CH_LLM_EXTRA_HEADERS` | JSON，额外请求头 |

## 词条文字

prompt 文件只有一份：`report/prompts/research.md`，`PROMPT_VERSION` 随它升级；**另有第二段提示词内联在代码里**（`research.py` 的 `REPAIR_HEAD`），只在校验没过时发出，落库记为 `prompt_version = research.md@9+repair`。**一份 prompt 服务所有链**：`__CHAIN__` 按 `config.chain_name()` 替换，`__THESIS__` 按 `config.chain_thesis()` 取链 yaml 的 `thesis:`（没登记就换成 `NO_THESIS`）。

| 规则 | 说明 / 反例 |
| --- | --- |
| 篇幅上限写在 prompt 里，代码只在超长时记日志、**不退回**（丢失一个词条即没有链下分）。上限在 `report/schema.py` 的 `CAPS`：`concl` 500（代码下限 160）、五个分项各 200、`badge` 16。 | 同一个字段有**两个**判定点：`ask` 决定是否重问、`one` 决定是否丢弃该币。 |
| 涉及源码 / 权限 / LP 的句子必须**一字不改**地引用事实表 `【安全】` 行的原文；调研必须带安全块（`_facts_line` 一并读 `safety_json`）。 | 不带安全块，词条会始终写「安全块三项全部未判定」；卡片曾一边显示「LP 已锁」，一边这样写。 |
| 链接统一成「说明 ＋ 可点击词」：`segments.py` 把 anchor / markdown / 裸 URL 都变成 link 段，前端 `Rich.tsx` 渲染成 `target="_blank"` 的 `<a>`。 | **全链路没有 `dangerouslySetInnerHTML`** —— 不应让模型文本直接进 HTML。 |
| 页脚列所有入口，正文不放链接：交易页 `GMGN ｜ Debot ｜ DexScreener`，然后 `X ｜ TG ｜ GitHub` 与**第一个**官网，全是文字下划线链接、没有打开图标。 | 反例：做成一排七个外链图标，基本只剩图标。 |
| 三条纪律：① `concl` 与 `narr_text` **严禁重复**（没有新内容就留空）；② 提到外部信息必须附**实读到**的原文 URL；③ `social` 只写判断、用互动率与发帖节奏说话，**不放链接、不以粉丝数作为卖点**。 | 新项目的粉丝数不足以构成证据。 |
| 结论写法：五段（定位 / 实质 / 亮点 / 风险 / 收尾）、**不加小标题**，第一句必须是身份句（链 ＋ 赛道 ＋ 定位）且**叙事先行**；**不写观点句**（「本批唯一…」一律不写，判断留给用户）、**不写数字段**（市值 / 流动性 / 筹码卡片上都有）。 | 卡片**不为叙事单开一块** —— 项目自己的故事落在结论里；`narr_text` 写的是「在不在本链主线上」，两者不应重复。 |
| 写作输入必须带页面正文；页面读不到时那个币就**没有词条**。 | 反例：给模型一句「如无资料请据常理推断」，报告里就会出现不存在的官网与产品。 |
| **先重问一次，再降级**：`ask` 把上一次的 JSON 与校验器原文（`REPAIR_HEAD`）一起发回，要求一份完整重写，第二次仍不通过才降级。**「读不到」与「无内容」区分**：静态正文不足 `MIN_CHARS` 时返回 `None`，失败的页面不落库。**降级 ＝ 该币无词条**：不写「确定性拼装的正文」冒充调研；失败原因记入本轮 note，不阻塞整轮。 | 不重问的话，思考关掉后约四成草稿漏必填分项，直接损失卡片；把「页面空」当成「项目没有官网」，模型可见的信息中，这个项目就少一个入口。 |
| 链名分两个：`label` 是**雷达**的名字（侧栏、配置管理抽屉），`name` 才是**链**的名字（`config.chain_name()`，yaml 没写就回落 `label`）。写进文字的三处都用后者：写作 prompt 的 `__CHAIN__`、搜索词、设定页 `f_narrative` 的口径行。 | 反例：两者混用，一份 prompt 写死了 Arc，模型只能答出「与 Arc 无公开关系」。 |
| `f_narrative` 判「在不在本链主线上」：判据只有一句话，写在链 yaml 的 `thesis:`。它是**链的事实**不是设定口径 —— 一条链两套配置筛的是同一批币，主线跟着配置走会让同一个项目判出两个分。官方提到 / 转发 / 关注降级成 `badge`，**只展示不进分**；0–5 六档各一句话，档位之间不留空档，**判定方式由模型依据页面事实决定**。 | 反例：判「和这条链什么关系」，每张卡答的都是官方背书（user, 2026-10-06）。 |

## 为什么这么定

每一条都是由一个具体的错误纠正出来的；现行口径见右列。

| 曾经的错 | 现在写在哪 |
| --- | --- |
| `f_narrative` 判「和这条链什么关系」→ 每张卡答的都是官方有没有背书，要答的「在不在主线上」只提过一次、没定义 | 本文件 · 词条文字 |
| 官网候选仅取引擎的 web 命中，或仅认可判定为 `own` 的账号页 → 项目写在自己 X 主页里的官网从来不会成为候选，卡片没有官网行 | 本文件 · 链下调研 ｜ `features/README.md` · CA 搜索 |
| 词条看不到安全块 → 永远写「三项全部未判定」，卡片一边显示「LP 已锁」 | 本文件 · 词条文字 |
